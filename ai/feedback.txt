FEEDBACK COMPONENTS
====================

CRITICAL: This is a Svelte 5 component library (@keenmate/svelte-pure-admin).
- All components use Svelte 5 runes ($props, $state, $derived, $bindable)
- Content slots use Snippets ({@render children?.()}), NOT <slot />
- Internal BEM classes: pa-alert, pa-modal, pa-toast, pa-spinner, etc.
- CSS is provided by @keenmate/pure-admin-core (must be imported separately)
- Event handlers use lowercase: onclick, onclose, ondismiss (Svelte 5 native)

INSTALLATION
------------
npm install @keenmate/svelte-pure-admin

Import CSS in your layout:
<script>
  import '@keenmate/pure-admin-core/css';
</script>

=====================================================================
ALERT
=====================================================================

Inline notification banners for contextual messages.

PROPS:
  variant?: 'primary' | 'secondary' | 'success' | 'danger' | 'warning' | 'info' | 'light' | 'dark'
                             -- Alert color variant (default: 'primary')
  size?: 'sm' | 'lg'        -- Alert size
  themeColor?: 1-9           -- Theme color slot (pa-alert--color-N / pa-alert--outline-color-N)
  isDismissible?: boolean    -- Shows close button (default: false)
  isOutline?: boolean        -- Outline style (default: false; core has outline for
                                primary/success/danger/warning/info only — others stay solid)
  isMultiline?: boolean      -- Stack icon at the top of multi-line content (pa-alert--multiline)
  headingText?: string       -- Alert heading text (plain)
  heading?: Snippet          -- Rich heading content (wins over headingText); rendered INSIDE
                                the component's <h4 class="pa-alert__heading"> — don't add your own <h4>
  headingSize?: 'lg'         -- 'lg' = large heading (pa-alert__heading--lg)
  class?: string             -- Additional CSS classes
  icon?: Snippet             -- Icon snippet (enables complex layout with pa-alert__content wrapper)
  iconName?: string          -- Icon name rendered through <Icon> (same layout; the icon snippet wins)
  children?: Snippet         -- Alert body content
  list?: Snippet             -- List items rendered in pa-alert__list <ul>
  actions?: Snippet          -- Action buttons rendered in pa-alert__actions
  ondismiss?: () => void     -- Fired when alert is dismissed

IMPORTANT: When the icon snippet (or iconName) is provided, the alert switches to a complex
layout with pa-alert__icon + pa-alert__content wrapper. Without icon, it uses
a simple flat layout.

BASIC USAGE:

<Alert variant="success">Operation completed successfully.</Alert>

<Alert variant="danger">Something went wrong. Please try again.</Alert>

<Alert variant="warning">Your session will expire in 5 minutes.</Alert>

WITH HEADING:

<Alert variant="info" headingText="New Update Available">
  Version 2.1 is now available with performance improvements.
</Alert>

RICH HEADING (snippet):

<Alert variant="warning">
  {#snippet heading()}Deprecated: <code>oldApi()</code>{/snippet}
  Switch to the new API before 3.0.
</Alert>

OUTLINE STYLE:

<Alert variant="primary" isOutline>This is an outlined alert.</Alert>

<Alert variant="danger" isOutline headingText="Error">
  Connection to the server failed.
</Alert>

DISMISSIBLE:

<Alert variant="warning" isDismissible ondismiss={() => console.log('dismissed')}>
  This alert can be closed by the user.
</Alert>

COMPLEX ALERT WITH ICON:

<Alert variant="danger" headingText="Deployment Failed">
  {#snippet icon()}
    <svg>...</svg>
  {/snippet}
  The build process exited with code 1.
  {#snippet list()}
    <li>Missing environment variable: DATABASE_URL</li>
    <li>TypeScript compilation error in src/index.ts:42</li>
  {/snippet}
  {#snippet actions()}
    <button class="pa-btn pa-btn--sm pa-btn--danger">Retry Build</button>
    <button class="pa-btn pa-btn--sm pa-btn--secondary">View Logs</button>
  {/snippet}
</Alert>

SIZE VARIANTS:

<Alert variant="info" size="sm">Small compact alert.</Alert>

<Alert variant="info" size="lg" headingText="Large Alert">
  This is a larger alert with more visual prominence.
</Alert>

THEME COLOR:

<Alert variant="primary" themeColor={3}>
  Custom themed alert using theme color 3.
</Alert>

MODAL
=====================================================================

Dialog overlay with backdrop, header, body, and footer.

PROPS:
  id?: string                   -- Optional id on the modal root
  isOpen?: boolean (bindable)   -- Show/hide modal (default: false)
  size?: 'sm' | 'md' | 'lg' | 'xl' | 'xxl' | 'fw'
                                -- Modal size (default: 'md')
  variant?: 'primary' | 'success' | 'warning' | 'danger' | 'info'
                                -- Role colour of the modal (header colour inherits)
  isBanded?: boolean            -- Header AND footer as filled role-colour bands (pa-modal--banded);
                                   compose with variant for the colour
  placement?: 'center' | 'top' -- Where the dialog sits (default: 'center')
  isScrollable?: boolean        -- Scrollable body (default: false)
  isStatic?: boolean            -- Prevents ESC/backdrop close (default: false)
  titleText?: string            -- Modal title text
  titleIconName?: string        -- Leading icon name before the title, rendered through <Icon> (affordances like success / warning / danger / info / delete render the masked glyph)
  hasClose?: boolean            -- Show close button (default: true)
  shouldCloseOnEscape?: boolean -- Close on ESC key (default: true)
  shouldCloseOnBackdrop?: boolean -- Close on backdrop click (default: true; Escape is separate)
  beforeCloseCallback?: () => boolean | void
                                -- Return false to prevent closing
  onclose?: () => void          -- Fired after modal closes
  class?: string                -- Additional modal CSS classes
  bodyClass?: string            -- Additional body CSS classes
  footerClass?: string          -- Additional footer CSS classes
  header?: Snippet              -- Rich title content (overrides titleText); rendered INSIDE the
                                   component's <h3 class="pa-modal__title"> — don't add your own <h3>
  children?: Snippet            -- Modal body content
  footer?: Snippet              -- Modal footer content

IMPORTANT: isOpen is $bindable -- use bind:isOpen for two-way binding.
When isStatic is true, both ESC key and backdrop click are disabled.

WHEN TO USE MODAL vs DIALOG SERVICE:

  Use <Modal> directly when you need:
    - Complex body content: forms, formatted/multiline text, grids, tables, components
    - Custom header or footer layouts via snippets
    - Two-way data binding (bind:value on inputs inside the modal)
    - Full template power — anything you can write in a Svelte template

  Use dialogService when you need:
    - Simple programmatic confirm/alert/prompt with plain text messages
    - No template markup — just await the result from any function
    - Sequential dialog chains (await one after another)

  IMPORTANT: dialogService.custom() only renders the `message` as a <Paragraph>.
  There is NO way to pass Svelte snippets or components through the JS function.
  For rich content, always use <Modal> directly in your template.

BASIC USAGE:

<script lang="ts">
  import { Modal, Button } from '@keenmate/svelte-pure-admin';
  let showModal = $state(false);
</script>

<Button onclick={() => showModal = true}>Open Modal</Button>

<Modal bind:isOpen={showModal} titleText="Confirm Action">
  Are you sure you want to proceed?

  {#snippet footer()}
    <Button variant="secondary" onclick={() => showModal = false}>Cancel</Button>
    <Button variant="primary" onclick={() => { doAction(); showModal = false; }}>Confirm</Button>
  {/snippet}
</Modal>

SIZE VARIANTS:

<Modal bind:isOpen={showSm} titleText="Small Modal" size="sm">
  Compact dialog for simple confirmations.
  {#snippet footer()}
    <Button variant="primary" onclick={() => showSm = false}>OK</Button>
  {/snippet}
</Modal>

<Modal bind:isOpen={showLg} titleText="Large Modal" size="lg">
  Wider dialog for forms and detailed content.
  {#snippet footer()}
    <Button variant="secondary" onclick={() => showLg = false}>Cancel</Button>
    <Button variant="primary">Save</Button>
  {/snippet}
</Modal>

<Modal bind:isOpen={showFw} titleText="Full Width" size="fw">
  Full-width dialog spanning the entire viewport.
  {#snippet footer()}
    <Button variant="secondary" onclick={() => showFw = false}>Close</Button>
  {/snippet}
</Modal>

THEMED MODAL:

  This action cannot be undone. All data will be permanently deleted.
  {#snippet footer()}

BANDED + TITLE ICON:

  Header and footer are filled warning-colour bands, body stays neutral.
  {#snippet footer()}

SCROLLABLE BODY:

  <div style="height: 2000px;">
    Very long content that scrolls within the modal body...
  </div>

FORCED CHOICE (ESC still closes, backdrop click does not):

STATIC MODAL (NO CLOSE ON ESC/BACKDROP):

  let hasUnsavedChanges = $state(false);

  function beforeClose(): boolean {
    if (hasUnsavedChanges) {
      return false; // Prevent closing

    return true; // Allow closing

<Modal
  bind:isOpen={showModal}
  titleText="Edit Profile"
  beforeCloseCallback={beforeClose}
  onclose={() => console.log('modal closed')}
>
  <input oninput={() => hasUnsavedChanges = true} />
  {#snippet footer()}
    <Button variant="secondary" onclick={() => { hasUnsavedChanges = false; showModal = false; }}>
      Discard

  {/snippet}
</Modal>

TOAST + TOAST CONTAINER
=====================================================================

Notification toasts with auto-dismiss and optional progress bar.

TOAST PROPS:
  variant?: 'primary' | 'success' | 'danger' | 'warning' | 'info'
                                 -- Toast color (default: 'primary')
  themeColor?: 1-9               -- Theme color slot (overrides variant)
  isFilled?: boolean             -- Full-colour background (default: false)
  titleText: string              -- Toast title (REQUIRED)
  messageText: string            -- Toast message (REQUIRED)
  isVisible?: boolean (bindable) -- Show/hide toast (default: true)
  duration?: number              -- Auto-dismiss in ms, 0 for persistent (default: 5000)
  hasProgress?: boolean          -- Show progress bar (default: false)
  progressColor?: string         -- Custom progress bar colour
  maxWidth?: string              -- Custom max-width (e.g. '50rem')
  icon?: Snippet                 -- Custom icon
  iconName?: string              -- Icon name rendered through <Icon> (the icon snippet wins)
  actions?: Snippet              -- Buttons rendered in pa-toast__actions
  onclose?: () => void           -- Fired when toast closes
  class?: string                 -- Additional CSS classes

TOAST CONTAINER PROPS:
  placement?: 'top-end' | 'top-center' | 'top-start' | 'bottom-end' | 'bottom-center' | 'bottom-start'
                                 -- Screen corner for the stack (default: 'top-end')
  class?: string                 -- Additional CSS classes
  children?: Snippet             -- Toast children (declarative toasts)

ToastContainer also renders toasts queued through toastService whose
placement matches its own (see TOAST SERVICE below).

IMPORTANT: Positions use logical directions (start/end), NOT physical (left/right).
This ensures correct positioning in RTL layouts. 'top-end' = top-right in LTR.

BASIC USAGE:

<ToastContainer placement="top-end">
  <Toast
    variant="success"
    titleText="Saved"
    messageText="Your changes have been saved."
  />
</ToastContainer>

WITH PROGRESS BAR:

<ToastContainer placement="top-end">
  <Toast
    variant="info"
    titleText="Uploading"
    messageText="File upload in progress..."
    hasProgress
    duration={8000}
  />
</ToastContainer>

PERSISTENT TOAST (NO AUTO-DISMISS):

<Toast
  variant="warning"
  titleText="Connection Lost"
  messageText="Attempting to reconnect..."
  duration={0}
/>

COMPLETE TOAST SYSTEM:

<script lang="ts">
  import { Toast, ToastContainer, Button } from '@keenmate/svelte-pure-admin';

  type ToastData = {
    id: number;
    variant: 'success' | 'danger' | 'warning' | 'info';
    title: string;
    message: string;
  };

  let toasts = $state<ToastData[]>([]);
  let nextId = 0;

  function addToast(variant: ToastData['variant'], title: string, message: string) {
    toasts = [...toasts, { id: nextId++, variant, title, message }];
  }

  function removeToast(id: number) {
    toasts = toasts.filter(t => t.id !== id);
  }
</script>

<Button variant="success" onclick={() => addToast('success', 'Success', 'Item saved.')}>
  Show Success Toast
</Button>
<Button variant="danger" onclick={() => addToast('danger', 'Error', 'Something failed.')}>
  Show Error Toast
</Button>

<ToastContainer placement="top-end">
  {#each toasts as toast (toast.id)}
    <Toast
      variant={toast.variant}
      titleText={toast.title}
      messageText={toast.message}
      hasProgress
      duration={5000}
      onclose={() => removeToast(toast.id)}
    />
  {/each}
</ToastContainer>

POSITION VARIANTS:

<ToastContainer placement="top-end">...</ToastContainer>
<ToastContainer placement="top-center">...</ToastContainer>
<ToastContainer placement="top-start">...</ToastContainer>
<ToastContainer placement="bottom-end">...</ToastContainer>
<ToastContainer placement="bottom-center">...</ToastContainer>
<ToastContainer placement="bottom-start">...</ToastContainer>

TOAST SERVICE (programmatic — preferred over managing toast arrays):

<!-- once in +layout.svelte, one container per placement you use -->
<ToastContainer placement="top-end" />

toastService.success('Saved!');                       // also .danger/.warning/.info/.primary
toastService.danger({ titleText: 'Failed', messageText: 'Could not save' });
const id = toastService.show({
  titleText: 'Working', messageText: '...', variant: 'info',
  duration: 0,                    // persistent
  hasProgress: true,
  placement: 'bottom-end',        // routes to the matching container (default 'top-end')
  actions: [{ label: 'Retry', variant: 'secondary', onclick: (id) => retry(), keepOpen: false }]
});
toastService.dismiss(id);  toastService.dismissAll();

ToastOptions: titleText, messageText, variant, themeColor, isFilled, duration,
hasProgress, progressColor, maxWidth, actions (ToastAction[]), iconClass (override —
the icon is derived from variant by default), class, placement.
Exports: toastService, toastStore, DEFAULT_TOAST_PLACEMENT, types ToastPlacement / ToastVariant.

LOADER
=====================================================================

Advanced animated loaders: dots, bars, pulse, ring, wave, grid, ripple, dual-ring.
For simple spinning indicators, use Spinner instead.

PROPS:
  type?: 'dots' | 'bars' | 'pulse' | 'ring' | 'wave' | 'grid' | 'ripple' | 'dual-ring'
                              -- Loader animation type (default: 'dots')
  size?: 'default' | 'lg'    -- Loader size
  variant?: 'primary' | 'secondary' | 'success' | 'danger' | 'warning' | 'info'
                              -- Role colour (set on the wrapper as currentColor)
  class?: string              -- Additional CSS classes

BASIC USAGE:

<Loader type="dots" />
<Loader type="bars" />
<Loader type="pulse" />
<Loader type="ring" />
<Loader type="wave" />
<Loader type="grid" />
<Loader type="ripple" />
<Loader type="dual-ring" />

LARGE SIZE:

<Loader type="dots" size="lg" />
<Loader type="wave" size="lg" variant="primary" />

COLOR VARIANTS:

<Loader type="bars" variant="success" />
<Loader type="pulse" variant="danger" />
<Loader type="ring" variant="warning" />

NOTE: 'dots' renders 3 spans, 'bars' and 'wave' render 5 spans, 'grid' 9 spans;
'pulse', 'ring', 'ripple' and 'dual-ring' are CSS-only (no child spans).
Colour is currentColor (variant sets it on the wrapper); grid/ripple/dual-ring are monochrome.

TOOLTIP
=====================================================================

Hover-activated text tooltip using Floating UI for smart positioning.

PROPS:
  text: string                                  -- Tooltip text (REQUIRED)
  placement?: 'top' | 'end' | 'bottom' | 'start'
                                                -- Placement (default: 'top')
  variant?: 'primary' | 'success' | 'warning' | 'danger' | 'color-1' ... 'color-9'
                                                -- Color variant
  isMultiline?: boolean                         -- 20rem width, left-aligned (default: false)
  isHelp?: boolean                              -- Question mark cursor (default: false)
  isKeyword?: boolean                           -- Dotted-underline keyword trigger (default: false)
  class?: string                                -- Additional CSS classes
  children?: Snippet                            -- Trigger element content

IMPORTANT: Requires Floating UI (@floating-ui/dom) loaded globally as
window.FloatingUIDOM. Without it, a console warning is shown and
positioning may not work correctly.

BASIC USAGE:

<Tooltip text="This is a tooltip">
  Hover over me
</Tooltip>

POSITION VARIANTS:

<Tooltip text="Top tooltip" placement="top">Top</Tooltip>
<Tooltip text="End tooltip" placement="end">End</Tooltip>
<Tooltip text="Bottom tooltip" placement="bottom">Bottom</Tooltip>
<Tooltip text="Start tooltip" placement="start">Start</Tooltip>

COLOR VARIANTS:

<Tooltip text="Primary" variant="primary">Hover</Tooltip>
<Tooltip text="Success" variant="success">Hover</Tooltip>
<Tooltip text="Warning" variant="warning">Hover</Tooltip>
<Tooltip text="Danger" variant="danger">Hover</Tooltip>

MULTILINE:

<Tooltip
  text="This is a longer tooltip that wraps to multiple lines for detailed explanations."
  isMultiline
>
  Hover for details
</Tooltip>

HELP CURSOR:

  What is this?
</Tooltip>

NOTE: placement is logical (start/end, NOT left/right) — the component maps it
to Floating UI's physical side for the current text direction, so it flips in RTL.

POPOVER

Click-triggered rich content overlays using Floating UI and portal pattern.

POPOVER PROPS:

SETUP (in +layout.svelte):

<script lang="ts">
  import { PopoverContainer } from '@keenmate/svelte-pure-admin';

<slot />
<PopoverContainer />

BASIC USAGE:

</Popover>

POPCONFIRM
=====================================================================

Small confirmation dialog anchored to a trigger element. Perfect for
delete confirmations and quick yes/no decisions.

PROPS:
  isOpen?: boolean (bindable)          -- Show/hide popconfirm (default: false)
  messageText: string                  -- Confirmation message (REQUIRED)
  placement?: 'top' | 'bottom' | 'start' | 'end'
                                       -- Placement (default: 'bottom')
  iconVariant?: 'danger' | 'warning' | 'info' -- Severity colour of the built-in icon
  isCompact?: boolean                  -- Compact size (default: false)
  confirmText?: string                 -- Confirm button text (default: i18n)
  cancelText?: string                  -- Cancel button text (default: i18n)
  confirmVariant?: string              -- Confirm button color (default: 'primary')
  trigger?: HTMLElement | null         -- Trigger element for positioning
  onconfirm?: () => void               -- Fired on confirm
  oncancel?: () => void                -- Fired on cancel
  class?: string                       -- Additional CSS classes

IMPORTANT: isOpen is $bindable. You must provide the trigger element reference
for Floating UI positioning. Requires Floating UI loaded globally.

BASIC USAGE:

<script lang="ts">
  import { Popconfirm, Button } from '@keenmate/svelte-pure-admin';

  let showConfirm = $state(false);
  let triggerEl: HTMLElement;

  function handleConfirm() {
    console.log('Confirmed!');
  }
</script>

<button
  bind:this={triggerEl}
  onclick={() => showConfirm = !showConfirm}
  class="pa-btn pa-btn--danger"
>
  Delete Item
</button>

<Popconfirm
  bind:isOpen={showConfirm}
  messageText="Are you sure you want to delete this item?"
  trigger={triggerEl}
  confirmVariant="danger"
  onconfirm={handleConfirm}
  oncancel={() => console.log('Cancelled')}
/>

WITH ICON:

<Popconfirm
  bind:isOpen={showConfirm}
  messageText="This action cannot be undone."
  iconVariant="danger"
  trigger={triggerEl}
  confirmVariant="danger"
  confirmText="Yes, delete"
  cancelText="No, keep it"
  onconfirm={handleDelete}
/>

COMPACT MODE:

<Popconfirm
  bind:isOpen={showConfirm}
  messageText="Remove?"
  isCompact
  trigger={triggerEl}
  onconfirm={handleRemove}
/>

NOTE: placement is logical (start/end, NOT left/right). Clicking outside closes
the popconfirm automatically.


=====================================================================
DIALOG SERVICE + DIALOG CONTAINER
=====================================================================

Promise-based programmatic dialog system. No need to manage modal state
manually -- just await the result.

SETUP (required once in +layout.svelte):

<script lang="ts">
  import { DialogContainer } from '@keenmate/svelte-pure-admin';
</script>

<slot />
<DialogContainer />

IMPORTS:

import { dialogService } from '@keenmate/svelte-pure-admin';

COMMON OPTIONS (every dialog type):
  title?: string
  message?: string            -- Plain text (rendered as a Paragraph)
  variant?: 'primary' | 'success' | 'warning' | 'danger' | 'info'  (DialogVariant)
  isBanded?: boolean          -- Banded header + footer in the variant colour
  icon?: string | false       -- Title icon; derived from variant when omitted
                                 (success/warning/danger/info glyph, none for primary);
                                 pass a pa-icon name (e.g. 'delete') to override, false to hide
  size?: 'sm' | 'md' | 'lg' | 'xl'   (DialogSize)
  placement?: 'center' | 'top'       (DialogPlacement)
  closeOnBackdrop?: boolean   -- Backdrop click dismisses (default true; prompt: false).
                                 Escape still cancels.
  class? / bodyClass? / footerClass?: string


CONFIRM DIALOG
--------------
Returns Promise<boolean> -- true if confirmed, false if cancelled.

const result = await dialogService.confirm({
  title: 'Delete User',
  message: 'Are you sure you want to delete this user? This cannot be undone.',
  confirmText: 'Delete',
  cancelText: 'Cancel',
  variant: 'danger',
  confirmVariant: 'danger'
});

if (result) {
  await deleteUser(userId);
}

CONFIRM OPTIONS (+ common):
  confirmText?: string        -- Confirm button text (default: i18n 'OK')
  cancelText?: string         -- Cancel button text (default: i18n 'Cancel')
  confirmVariant?: DialogVariant -- Confirm button color

BANDED / FORCED CHOICE:

const ok = await dialogService.confirm({
  title: 'Delete project?', message: 'This cannot be undone.',
  variant: 'danger', isBanded: true, icon: 'delete', closeOnBackdrop: false
});


ALERT DIALOG
------------
Returns Promise<void> -- resolves when user clicks OK.

await dialogService.alert({
  title: 'Success!',
  message: 'Your profile has been updated.',
  variant: 'success'
});

ALERT OPTIONS (+ common):
  okText?: string             -- OK button text (default: i18n 'OK')


PROMPT DIALOG
-------------
Returns Promise<string | null> -- string value if submitted, null if cancelled.

const name = await dialogService.prompt({
  title: 'Rename File',
  message: 'Enter a new name for the file:',
  defaultValue: 'document.txt',
  placeholder: 'filename.ext',
  confirmText: 'Rename',
  cancelText: 'Cancel'
});

if (name !== null) {
  await renameFile(fileId, name);
}

PROMPT WITH VALIDATION:

const email = await dialogService.prompt({
  title: 'Enter Email',
  message: 'Provide your email address:',
  placeholder: 'you@example.com',
  validator: (value) => {
    if (!value.includes('@')) return 'Please enter a valid email';
    return true;
  }
});

PROMPT OPTIONS (+ common):
  defaultValue?: string       -- Initial input value
  placeholder?: string        -- Input placeholder
  confirmText?: string
  cancelText?: string
  validator?: (value: string) => true | string
                              -- Return true if valid, error string if invalid
  closeOnBackdrop?: boolean   -- Defaults to false for prompts


CUSTOM DIALOG
-------------
Returns Promise<T> -- the value of the clicked button, or dismissValue.

const action = await dialogService.custom({
  title: 'Save Changes?',
  message: 'You have unsaved changes. What would you like to do?',
  buttons: [
    { label: 'Discard', value: 'discard', variant: 'danger' },
    { label: 'Save as Draft', value: 'draft', variant: 'secondary' },
    { label: 'Save & Publish', value: 'publish', variant: 'success' }
  ],
  dismissValue: 'discard'
});

if (action === 'publish') {
  await saveAndPublish();
} else if (action === 'draft') {
  await saveAsDraft();
}

CUSTOM BUTTON OPTIONS:
  label: string               -- Button text
  value: T                    -- Value returned when clicked
  variant?: 'primary' | 'secondary' | 'success' | 'danger' | 'warning' | 'info' | 'light' | 'dark'
                              -- Button color (default: 'secondary')
  isOutline?: boolean         -- Outline button style
  class?: string              -- Additional button CSS class
  isDisabled?: boolean        -- Disable button

CUSTOM DIALOG OPTIONS (+ common):
  buttons: DialogButton<T>[]  -- Array of button definitions
  dismissValue?: T            -- Value when closed via ESC/backdrop


=====================================================================
NOTIFICATION BELL + NOTIFICATIONS PANEL
=====================================================================

NotificationBell = navbar bell button + unread badge + panel anchor (.pa-notifications).
NotificationsPanel = the dropdown (or full-page list) of notifications.

NOTIFICATION BELL PROPS:
  isOpen?: boolean (bindable)  -- Panel open state, toggled by the bell (default: false)
  count?: number | string      -- Unread badge; hidden when unset / 0 / ''
  ariaLabel?: string           -- Bell button label (default: i18n)
  class?: string
  bell?: Snippet               -- Custom bell icon (default: masked pa-icon--bell)
  children?: Snippet           -- Put <NotificationsPanel bind:isOpen> here
  onclick?: () => void         -- After toggling isOpen

NOTIFICATIONS PANEL PROPS:
  items?: NotificationItem[]   -- Data (ignored when customItems is given)
  isPageView?: boolean         -- Bare full-page list (--page), no dropdown wrapper
  isOpen?: boolean (bindable)  -- Dropdown open state (ignored when isPageView)
  titleText?: string           -- Header heading
  markAllReadText?: string     -- "Mark all as read" text
  footerText?: string          -- Footer link text (dropdown only)
  footerHref?: string          -- Footer link href (default: '#all-notifications')
  hasCheckboxes?: boolean      -- Leading checkbox per item (page view bulk actions)
  class?: string
  itemActions?: Snippet<[NotificationItem]>  -- Per-item actions
  customItems?: Snippet        -- Fully custom item rendering
  header?: Snippet / footer?: Snippet        -- Replace default header / footer
  onmarkallread?: () => void
  onitemclick?: (item) => void
  onitemtoggle?: (item, checked: boolean) => void

NotificationItem: { id, titleText, messageText, timeText, isUnread?,
  iconText?, iconClass?, iconVariant?: 'primary'|'success'|'warning'|'danger'|'secondary' }

BASIC USAGE:

<script lang="ts">
  import { NotificationBell, NotificationsPanel, type NotificationItem } from '@keenmate/svelte-pure-admin';
  let isNotificationsOpen = $state(false);
  let items = $state<NotificationItem[]>([
    { id: 1, titleText: 'Build passed', messageText: 'main #482', timeText: '2m ago', isUnread: true, iconVariant: 'success' }
  ]);
</script>

<NotificationBell bind:isOpen={isNotificationsOpen} count={items.filter(i => i.isUnread).length}>
  <NotificationsPanel bind:isOpen={isNotificationsOpen} {items} titleText="Notifications"
    onmarkallread={() => items = items.map(i => ({ ...i, isUnread: false }))} />
</NotificationBell>

EXAMPLE 1: FORM WITH VALIDATION ALERTS AND MODAL CONFIRM

<script lang="ts">
  import { Alert, Modal, Button, dialogService } from '@keenmate/svelte-pure-admin';

  let errors = $state<string[]>([]);
  let showSuccess = $state(false);

  async function handleSubmit() {
    errors = [];

    // Validate
    if (!formData.name) errors.push('Name is required');
    if (!formData.email) errors.push('Email is required');

    if (errors.length > 0) return;

    // Confirm before submitting
    const confirmed = await dialogService.confirm({
      title: 'Submit Form',
      message: 'Are you sure you want to submit this form?',
      confirmText: 'Submit',
      variant: 'primary'
    });

    if (!confirmed) return;

    await submitForm(formData);
    showSuccess = true;
  }
</script>

{#if errors.length > 0}
  <Alert variant="danger" isDismissible headingText="Validation Failed">
    {#snippet list()}
      {#each errors as error}
        <li>{error}</li>
      {/each}
    {/snippet}
  </Alert>
{/if}

{#if showSuccess}
  <Alert variant="success" isDismissible ondismiss={() => showSuccess = false}>
    Form submitted successfully!
  </Alert>
{/if}


EXAMPLE 2: CRUD OPERATIONS WITH TOAST NOTIFICATIONS

<script lang="ts">
  import {
    Button, Toast, ToastContainer, dialogService
  } from '@keenmate/svelte-pure-admin';

  type ToastItem = {
    id: number;
    variant: 'success' | 'danger' | 'warning' | 'info';
    title: string;
    message: string;
  };

  let toasts = $state<ToastItem[]>([]);
  let toastId = 0;

  function notify(variant: ToastItem['variant'], title: string, message: string) {
    toasts = [...toasts, { id: toastId++, variant, title, message }];
  }

  async function handleDelete(item: Item) {
    const confirmed = await dialogService.confirm({
      title: 'Delete Item',
      message: `Are you sure you want to delete "${item.name}"?`,
      variant: 'danger',
      confirmVariant: 'danger',
      confirmText: 'Delete'
    });

    if (!confirmed) return;

    try {
      await api.deleteItem(item.id);
      notify('success', 'Deleted', `"${item.name}" has been deleted.`);
    } catch (e) {
      notify('danger', 'Error', `Failed to delete "${item.name}".`);
    }
  }

  async function handleSave(item: Item) {
    try {
      await api.saveItem(item);
      notify('success', 'Saved', 'Changes saved successfully.');
    } catch (e) {
      notify('danger', 'Error', 'Failed to save changes.');
    }
  }
</script>

<ToastContainer placement="top-end">
  {#each toasts as toast (toast.id)}
    <Toast
      variant={toast.variant}
      titleText={toast.title}
      messageText={toast.message}
      hasProgress
      duration={4000}
      onclose={() => toasts = toasts.filter(t => t.id !== toast.id)}
    />
  {/each}
</ToastContainer>

=====================================================================
CRITICAL REMINDERS
=====================================================================

DO:
  - Import CSS from @keenmate/pure-admin-core separately
  - Place DialogContainer, PopoverContainer, ToastContainer at root layout
  - Use bind:isOpen for two-way binding on Modal, Popconfirm, SlidePanel, DetailView
  - Use beforeCloseCallback to prevent modal close (return false)
  - Use dialogService for programmatic confirm/alert/prompt (await the result)
  - Use logical placements for ToastContainer (top-end, bottom-start, etc.)
  - Load Floating UI globally for Tooltip, Popover, Popconfirm positioning

DO NOT:
  - Use <slot> syntax (Svelte 5 uses Snippets: {@render children?.()})
  - Use export let (Svelte 5 uses $props())
  - Use camelCase event handlers (onclick not onClick, onclose not onClose)
  - Use physical positions for toast (top-right is WRONG, use top-end)
  - Nest PopoverContainer inside other components (must be at root)
  - Forget to include DialogContainer when using dialogService
  - Use multiple PopoverContainer instances (only one is needed)
