THEMING AND CUSTOMIZATION
=========================

CRITICAL: This is a Svelte 5 component library (@keenmate/svelte-pure-admin).
Theming works through CSS custom properties defined by @keenmate/pure-admin-core
(and its foundation, @keenmate/pure-css): foundation tokens are --pc-*
(colours, radii, layout), component tokens are --pa-* (e.g. --pa-card-bg).
Themes set --base-* source tokens that the --pc-* / --pa-* tokens read. Colour
slots 1-9 (--pc-palette-N) provide theme-defined colours available through
utility classes and the themeColor prop.

CSS IMPORT
----------
Every app needs the framework CSS. Without it, no components render correctly.

Unthemed default (neutral look) - in your root layout or app entry:

<script>
  import '@keenmate/pure-admin-core/css';
</script>

Or in a global CSS file:

@import '@keenmate/pure-admin-core/css';

This provides all base styles, BEM classes (pa-*), utilities and default CSS
variable values.

A THEME CSS FILE IS SELF-CONTAINED: it compiles core in. With a theme, load the
theme's CSS (it replaces core's CSS; loading core first is harmless but
redundant). Use themes built against the core version you depend on
(core 3.3.0-rc09 for 2.0.0-rc01) - an older theme misses newer classes/tokens.


THEMES
------
Themes are distributed from pureadmin.io as ZIP packages (css/<id>.css +
theme.json manifest + fonts). Install them with the pureadmin CLI, which reads
pureadmin.json and extracts each theme into themesDir:

// pureadmin.json
{
  "themesDir": "static/themes",
  "themes": { "audi": {}, "dark": {}, "corporate": {} }
}

npx @keenmate/pureadmin themes install

Available themes include: audi, ayu, cobalt2, corporate, dark, darkmatter,
dracula, express, gruvbox, minimal, night-owl, one-dark, tokyo-night.

NOTE: the old npm packages @keenmate/pure-admin-theme-* are core 2.x builds -
do not use them with svelte-pure-admin 2.x.

Static theme (single theme, no switching) - link the extracted CSS:

<link rel="stylesheet" href="/themes/audi/css/audi.css">


THEME SWITCHING AT RUNTIME
---------------------------
For dynamic theme switching, load themes as CSS files (not JS imports) and swap
them at runtime via a <link> element (SettingsPanel does this for you, using
the same id 'pa-theme-css').

Manual theme switching approach:

<script lang="ts">
  function setTheme(cssPath: string) {
    let themeLink = document.getElementById('pa-theme-css') as HTMLLinkElement;
    if (!themeLink) {
      themeLink = document.createElement('link');
      themeLink.id = 'pa-theme-css';
      themeLink.rel = 'stylesheet';
      document.head.appendChild(themeLink);
    }
    themeLink.href = cssPath;
  }

  // Switch to Audi theme
  setTheme('/themes/audi/css/audi.css');

  // Switch to Corporate theme
  setTheme('/themes/corporate/css/corporate.css');
</script>

Theme CSS files must be served as static files (e.g. SvelteKit static/) so
they are available as URLs. Add a render-blocking <link> in app.html for the
initial theme to avoid a flash of unstyled content.


SETTINGS PANEL COMPONENT
-------------------------
SettingsPanel provides a floating gear-icon panel that handles theme switching,
dark mode, layout width, sidebar options, font settings, and more.

import { SettingsPanel } from '@keenmate/svelte-pure-admin';
import type { ThemeOption } from '@keenmate/svelte-pure-admin';

Props:
  availableThemes?: ThemeOption[]    (if not provided, theme selector is hidden)
  defaultTheme?: string             (defaults to first theme id)
  onsettingschange?: (settings: SettingsPanelState) => void

ThemeOption interface:

interface ThemeOption {
  id: string;       // e.g., 'audi', 'express'
  name: string;     // e.g., 'Audi', 'Express'
  cssPath: string;  // e.g., '/themes/audi/css/audi.css'
  // Optional - copied from the theme's theme.json manifest. When present, the
  // panel builds its Mode and Color Variant selectors from them:
  colorVariants?: ThemeColorVariantOption[] | ThemeColorVariantsLegacy;
  modes?: ThemeModesLegacy;          // legacy manifest schema
  modeCssClass?: string;             // default 'pc-mode-{mode}'
  variantCssClass?: string;          // default 'pa-color-{variant}'
}

ThemeColorVariantOption = { id?, name?, description?, file?, modes?: ThemeModeOption[] }
ThemeModeOption         = { id: string ('light' | 'dark'), name?, default?: boolean }
(all exported as types). Without manifest data the panel offers light / dark / auto.

Complete SettingsPanel setup:

<script lang="ts">
  import { SettingsPanel } from '@keenmate/svelte-pure-admin';
  import type { ThemeOption } from '@keenmate/svelte-pure-admin';

  const themes: ThemeOption[] = [
    { id: 'audi', name: 'Audi', cssPath: '/themes/audi/css/audi.css' },
    { id: 'dark', name: 'Dark', cssPath: '/themes/dark/css/dark.css' },
    { id: 'corporate', name: 'Corporate', cssPath: '/themes/corporate/css/corporate.css' }
  ];

  function handleSettingsChange(settings: any) {
    console.log('Settings changed:', settings);
  }
</script>

<SettingsPanel
  availableThemes={themes}
  defaultTheme="audi"
  onsettingschange={handleSettingsChange}
/>

SettingsPanel manages these settings with localStorage persistence:

  theme            - Selected theme ID (localStorage key: 'theme')
  themeMode        - a manifest mode id ('light' | 'dark') or 'auto' (key: 'theme-mode')
  colorVariant     - manifest colour variant id, '' = theme default (key: 'color-variant')
  containerWidth   - 'fluid' | 'sm' | 'md' | 'lg' | 'xl' | '2xl' (key: 'container-width')
  searchPosition   - '' | 'navbar-inline' | 'navbar-compact' | 'sidebar' |
                     'navbar-typeahead' | 'sidebar-typeahead' (key: 'search-position';
                     sets body[data-search-position])
  commandPaletteSize - '' (608px) | 'sm' | 'lg' | 'xl' (key: 'command-palette-size')
  sidebarBehavior  - 'hide' | 'icon-collapse' | 'overlay' (key: 'sidebar-behavior')
  sidebarResizable - boolean (key: 'sidebar-resizable')
  sidebarMode      - '' | 'sticky' (key: 'sidebar-mode')
  compactMode      - boolean (key: 'compact-mode')
  rtlMode          - boolean (key: 'rtl-mode')
  fontSize         - 'small' | 'default' | 'large' | 'xlarge' (key: 'font-size')
  fontFamily       - 'default' | 'serif' | 'mono' | 'cuprum' | etc. (key: 'font-family')
  profileHasAvatar - boolean (key: 'profile-no-avatar', inverted)
  profileIconOnlyTabs - boolean (key: 'profile-icon-only-tabs')

The sidebar's shown/hidden state (body.sidebar-hidden) is NOT a panel setting -
it belongs to your burger handler.

Mode and variant changes dispatch a 'pa:theme-change' CustomEvent on window
(detail: { kind: 'mode' | 'variant', mode?, variant? }) and emit 'theme:change'
on core's bus (window.pureAdmin.events) when core JS is loaded.


LIGHT / DARK / AUTO MODE
-------------------------
SettingsPanel offers the modes the theme's manifest declares (fallback: light
and dark), plus auto when both exist:

  light  - body gets class pc-mode-light
  dark   - body gets class pc-mode-dark
  auto   - follows the OS preference (prefers-color-scheme)

The class comes from the manifest's modeCssClass pattern (default
'pc-mode-{mode}'); body[data-theme] is set to the resolved mode too. Colour
variants add the variantCssClass pattern (default 'pa-color-{variant}') to body.

Auto mode uses core's OS-preference watcher (window.pureAdmin.colorScheme +
'colorscheme:change' on the core bus) when core JS is loaded, otherwise its own
matchMedia('(prefers-color-scheme: dark)') listener.

Manual dark mode (without SettingsPanel):

<script lang="ts">
  function setThemeMode(mode: 'light' | 'dark' | 'auto') {
    let resolvedMode = mode;

    if (mode === 'auto') {
      resolvedMode = window.matchMedia('(prefers-color-scheme: dark)').matches
        ? 'dark'
        : 'light';
    }

    document.body.classList.remove('pc-mode-light', 'pc-mode-dark');
    document.body.classList.add(`pc-mode-${resolvedMode}`);
  }

  // Apply dark mode
  setThemeMode('dark');

  // Follow OS preference
  setThemeMode('auto');
</script>


COLOR SLOTS (1-9)
------------------
Pure Admin defines 9 theme-specific colors (color slots). Each theme
assigns different colors to these slots. They are used via utility classes and
the themeColor prop on supported components.

ThemeColor type:

type ThemeColor = 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9;

CSS custom properties for color slots:

  --pc-palette-1 through --pc-palette-9              (slot colour)
  --pc-on-palette-1-text-color ... -9-text-color     (readable text on the slot)

Utility classes for color slots (no pa- prefix):

  Background:      bg-color-1      ... bg-color-9
  Text:            text-color-1    ... text-color-9
  Border colour:   border-color-1  ... border-color-9
  Surface (bg + readable text):  surface-color-1 ... surface-color-9
  Text on slot bg: text-on-color-1 ... text-on-color-9

Role equivalents exist too: bg-<role>, text-<role>, surface-<role>,
text-on-<role> (role = primary | secondary | success | warning | danger | info).

Using color slots in HTML:

<div class="surface-color-3">Slot 3 background with readable text</div>
<span class="text-color-5">Text in color slot 5</span>
<div class="border-color-1" style="border: 2px solid;">Border color slot 1</div>

Components that accept themeColor prop (themeColor={3} adds):

  Button / SplitButton - pa-btn--color-3 (pa-btn--outline-color-3 with isOutline)
  Badge         - pa-badge--color-3
  Alert         - pa-alert--color-3 (pa-alert--outline-color-3 with isOutline)
  Callout       - pa-callout--color-3
  Toast         - pa-toast--color-3 (pa-toast--filled-color-3 with isFilled)
  Fields        - pa-fields--color-3
  TableCard     - pa-table-card--color-3
  Input / NumberInput / DateInput / FileInput / RangeInput - pa-input--color-3
  Select        - pa-select--color-3
  Textarea      - pa-textarea--color-3
  FormHelp      - pa-form-help--color-3

Example - Badge with theme color:

<script lang="ts">
  import { Badge, type ThemeColor } from '@keenmate/svelte-pure-admin';
</script>

<Badge themeColor={1}>Color 1</Badge>
<Badge themeColor={2}>Color 2</Badge>
<Badge themeColor={3}>Color 3</Badge>
<Badge themeColor={4}>Color 4</Badge>
<Badge themeColor={5}>Color 5</Badge>

Example - Input with theme color:

<Input themeColor={3} placeholder="Themed input" />

Example - Alert with theme color:

<Alert themeColor={7}>This alert uses color slot 7.</Alert>

Example - Using color slots on Card headerClass:

<Card headerClass="surface-color-2" titleText="Card with themed header">
  Card body content.
</Card>

Each theme defines its own color palette for slots 1-9. For example:
  - Audi theme: grays, reds, and Audi brand colors
  - Corporate theme: professional blues and greens
  - Express theme: bold, vivid colors
  - Minimal theme: muted, desaturated tones


CSS CUSTOM PROPERTIES
---------------------
Foundation tokens are --pc-*; component tokens are --pa-* (e.g. --pa-card-bg).
Themes set the --base-* source values the --pc-* tokens read
(--pc-primary-color: var(--base-primary-color, ...)). Role colours end in
-color (--pc-primary-color, NOT --pc-primary).

Key CSS custom properties:

  Layout / surfaces:
    --pc-border-radius (-sm / -lg) - Border radii
    --pc-border-color              - Default border color
    --pc-main-bg / --pc-page-bg    - Content / page background
    --pc-subtle-bg                 - Subtle fill
    --pc-hover-bg / --pc-active-bg - Interactive states

  Role colours:
    --pc-primary-color (-hover / -active)
    --pc-secondary-color
    --pc-success-color / --pc-warning-color / --pc-danger-color / --pc-info-color
    --pc-<role>-text-color          - Role-tinted text readable on the page bg
    --pc-primary-bg-subtle (-hover) - Tinted primary background

  Text scale:
    --pc-text-color-1 ... --pc-text-color-4   (1 = strongest, 4 = faintest)
    (muted text in markup: the .text-muted utility)

  Components (example):
    --pa-card-bg                   - Card background

  Color slots:
    --pc-palette-1 ... --pc-palette-9

Override custom properties in your CSS (loaded after the theme):

:root {
  --base-primary-color: #e91e63;   /* source token: --pc-primary-color and web components follow */
  --base-palette-1: #1976d2;
  --pc-border-radius: 0.5rem;
}

Or scope overrides to a specific section (set the --pc-* / --pa-* token itself;
--pc-* values resolve at :root, so a scoped --base-* change won't reach them):

.my-custom-section {
  --pa-card-bg: #f5f5f5;
  --pc-border-color: #ddd;
}


CONTAINER WIDTHS
----------------
Content width is constrained by a pc-container-* class on <body> (SettingsPanel
manages it via the containerWidth setting; <Layout> has no size prop):

  pc-container-sm   - 768px
  pc-container-md   - 1024px
  pc-container-lg   - 1280px
  pc-container-xl   - 1600px
  pc-container-2xl  - 1920px
  (none)            - Fluid, full width

Manual container width (without SettingsPanel):

document.body.classList.add('pc-container-lg');


FONT OPTIONS
------------
SettingsPanel provides font size and font family switching.

Font sizes (applied as class on <html>):

  font-size-small   - 14px base
  font-size-default - 16px base (no class needed)
  font-size-large   - 18px base
  font-size-xlarge  - 20px base

Font families (applied as class on <body>):

  font-family-serif
  font-family-mono
  font-family-cuprum
  font-family-fira-sans-condensed
  font-family-manrope
  font-family-martel
  font-family-maven-pro
  font-family-monda
  font-family-play
  font-family-signika
  font-family-yanone-kaffeesatz

Manual font switching (without SettingsPanel):

// Set large font
document.documentElement.classList.add('font-size-large');

// Set monospace font
document.body.classList.add('font-family-mono');


SIDEBAR MODES
-------------
SettingsPanel controls several sidebar behaviors:

Sidebar behavior (how sidebar collapses):
  'hide'            - Hides sidebar completely when collapsed
  'icon-collapse'   - Shows icon-only rail when collapsed
                      (class pc-layout__sidebar--icon-collapse; <Sidebar isIconCollapse>)
  'overlay'         - Floating drawer on desktop (body.sidebar-overlay; the burger
                      toggles body.sidebar-visible, like the mobile drawer)

Sidebar collapsed state (owned by your burger handler, not the panel):
  body gets class: sidebar-hidden

Sidebar resizable:
  When sidebarResizable=true, the sidebar gets pc-layout__sidebar--resizable and
  core's sidebar-resize JS adds the .pc-sidebar-resize drag handle

Sidebar mode (scroll behavior):
  ''        - Sidebar scrolls with content (default)
  'sticky'  - Sidebar stays fixed on scroll

  Class applied: pc-layout--sticky (on body)

Manual sidebar control (without SettingsPanel):

// Collapse sidebar
document.body.classList.add('sidebar-hidden');

// Icon-only collapse
document.querySelector('.pc-layout__sidebar')?.classList.add('pc-layout__sidebar--icon-collapse');

// Sticky sidebar
document.body.classList.add('pc-layout--sticky');


RTL MODE
--------
SettingsPanel supports right-to-left mode.

When rtlMode=true:
  document.documentElement.setAttribute('dir', 'rtl');

When rtlMode=false:
  document.documentElement.setAttribute('dir', 'ltr');

All Pure Admin components use logical properties (start/end instead of left/right)
for full RTL support. Tooltip / Popconfirm placement is 'top' | 'bottom' | 'start'
| 'end' (mirrored under RTL). Utilities are logical-only: ms-*/me-*, ps-*/pe-*,
text-start/text-end, border-start/end, rounded-start/end (no ml-/mr-/pl-/pr-).


COMPACT MODE
------------
When compactMode=true, body gets class: compact-mode

This reduces padding, margins, and font sizes globally across all components.

Manual:
document.body.classList.add('compact-mode');


SEMANTIC COLOR VARIABLES
------------------------
Beyond color slots, themes define role colours for feedback/status:

  --pc-primary-color    - Primary / brand colour
  --pc-secondary-color  - Secondary colour
  --pc-success-color    - Success green
  --pc-warning-color    - Warning yellow/orange
  --pc-danger-color     - Danger red
  --pc-info-color       - Info blue

These are used by Alert, Badge, Button, Toast, and other components via their
variant prop ('primary', 'secondary', 'success', 'warning', 'danger', 'info').
In your own markup use the role utilities (text-<role>, bg-<role>,
surface-<role>, text-on-<role>). NOTE: .text-secondary is the secondary ROLE
colour - for muted / de-emphasised text use .text-muted.


COMPLETE THEMING SETUP EXAMPLE
-------------------------------

<script lang="ts">
  import {
    Layout, LayoutInner, LayoutContent,
    Navbar, AppHeader,
    Sidebar, SidebarItem,
    Main,
    SettingsPanel,
    Badge, Alert, Input, Card
  } from '@keenmate/svelte-pure-admin';
  import type { ThemeOption } from '@keenmate/svelte-pure-admin';

  const themes: ThemeOption[] = [
    { id: 'audi', name: 'Audi', cssPath: '/themes/audi/css/audi.css' },
    { id: 'dark', name: 'Dark', cssPath: '/themes/dark/css/dark.css' },
    { id: 'corporate', name: 'Corporate', cssPath: '/themes/corporate/css/corporate.css' }
  ];
</script>

<Layout>
  <Navbar>
    {#snippet start()}
      <AppHeader><h1>My App</h1></AppHeader>
    {/snippet}
  </Navbar>

  <LayoutInner>
    <Sidebar>
      <SidebarItem labelText="Dashboard" href="/" iconName="fa-solid fa-home" />
      <SidebarItem labelText="Settings" href="/settings" iconName="fa-solid fa-cog" />
    </Sidebar>

    <LayoutContent>
      <Main>
        <!-- Color slot badges -->
        <Badge themeColor={1}>Slot 1</Badge>
        <Badge themeColor={2}>Slot 2</Badge>
        <Badge themeColor={3}>Slot 3</Badge>

        <!-- Themed input -->
        <Input themeColor={5} placeholder="Color slot 5 input" />

        <!-- Themed alert -->
        <Alert themeColor={4}>This uses color slot 4.</Alert>

        <!-- Card with themed header -->
        <Card headerClass="surface-color-1" titleText="Themed Card">
          Content here.
        </Card>
      </Main>
    </LayoutContent>
  </LayoutInner>
</Layout>

<!-- Settings panel (floating gear icon) -->
<SettingsPanel availableThemes={themes} defaultTheme="audi" />


IMPORTANT NOTES
---------------
- Theme CSS is self-contained (includes core). Without a theme, import
  @keenmate/pure-admin-core/css. If you load both, the theme must come after core.
- Your own token overrides must load after the theme CSS.
- Color slots 1-9 change meaning per theme. Do not assume slot 3 = orange everywhere.
- SettingsPanel persists all settings to localStorage automatically.
- SettingsPanel applies settings to DOM on mount (loads from localStorage).
- The 'auto' theme mode uses prefers-color-scheme and listens for OS changes.
- pc-mode-light / pc-mode-dark classes on body control light/dark mode.
- Container width classes (pc-container-sm/md/lg/xl/2xl) go on body.
- Font size classes go on <html>. Font family classes go on <body>.
- Sidebar classes go on the .pc-layout__sidebar element or on body.
