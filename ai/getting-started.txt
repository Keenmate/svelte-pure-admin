GETTING STARTED
===============

CRITICAL: This is a Svelte 5 component library (NOT a Web Component)
- Requires Svelte 5 with runes API ($props, $state, $derived)
- Wraps @keenmate/pure-admin-core CSS framework into typed Svelte components
- Uses Snippets (not slots) for content composition
- All components output BEM-style pa-* classes internally
- Consumers never need to write CSS class names manually
- Works with SvelteKit 2.x out of the box

INSTALLATION
------------
npm install @keenmate/svelte-pure-admin @keenmate/pure-admin-core @keenmate/pure-css

# Or yarn
yarn add @keenmate/svelte-pure-admin @keenmate/pure-admin-core @keenmate/pure-css

# Or pnpm
pnpm add @keenmate/svelte-pure-admin @keenmate/pure-admin-core @keenmate/pure-css

Packages (2.0.0-rc01 is a pre-release: npm install @keenmate/svelte-pure-admin@rc):
- @keenmate/svelte-pure-admin — Svelte 5 component library (~200 components)
- @keenmate/pure-admin-core — CSS framework (the actual styles)
- @keenmate/pure-css — foundation layer (grid, utilities, app shell JS)

Peer dependencies (must already be in your project):
- @keenmate/pure-admin-core ^3.3.0-rc09 (a ^2.x range does NOT reach 3.x — bump explicitly)
- @keenmate/pure-css ^2.0.0-rc04
- svelte ^5.0.0

Themes compile core into their CSS: use themes rebuilt against core 3.3.0-rc09,
or newer classes (8px button-group gap, ripple, ...) will be missing.

CSS IMPORT
----------
You MUST import the Pure Admin CSS somewhere in your app.
The most common place is your root +layout.svelte:

<script>
  import '@keenmate/pure-admin-core/css';
</script>

Or in a global CSS file:

@import '@keenmate/pure-admin-core/css';

Without this import, components will render with no styles.
This is the single most common setup mistake.

THEMES
------
Themes are ZIP packages from pureadmin.io (css/<id>.css + theme.json + fonts),
installed with the pureadmin CLI (reads pureadmin.json, extracts into themesDir):

npx @keenmate/pureadmin themes install

A theme CSS file is self-contained (core is compiled in), so link it instead of
core's CSS. Use themes built against core 3.3.0-rc09 - older builds miss newer
classes/tokens. (The old npm @keenmate/pure-admin-theme-* packages are core 2.x
builds - do not use them with 2.0.)

<link rel="stylesheet" href="/themes/audi/css/audi.css">

Only one theme at a time. Theme overrides core CSS variables
(component tokens --pa-*, foundation tokens --pc-*).
See theming.txt for color customization and dark mode.

PROVIDER SETUP
--------------
Wrap your app in PureAdminProvider for configuration context.
Place it in your root +layout.svelte:

<script>
  import '@keenmate/pure-admin-core/css';
  import { PureAdminProvider } from '@keenmate/svelte-pure-admin';

  let { children } = $props();
</script>

<PureAdminProvider>
  {@render children()}
</PureAdminProvider>

With custom configuration:

<script>
  import '@keenmate/pure-admin-core/css';
  import { PureAdminProvider } from '@keenmate/svelte-pure-admin';

  let { children } = $props();

  const config = {
    app: {
      name: 'My Admin App',
      copyright: '2026 My Company',
      logo: '/logo.svg'
    },
    defaults: {
      pageSize: 25,
      locale: 'en-US',
      dateFormat: 'YYYY-MM-DD'
    },
    ui: {
      theme: 'light',
      sidebarCollapsed: false,
      animations: true
    }
  };
</script>

<PureAdminProvider {config}>
  {@render children()}
</PureAdminProvider>

PureAdminProvider:
- Merges your config with sensible defaults (mergeConfig)
- Provides config to all child components via Svelte context
- Sets up global keyboard shortcut listener (Shift+? for help);
  pass shouldHandleShortcuts={false} to turn it off (default true)
- Initializes i18n if i18n config is present
- Registers icon providers (iconProviders prop) used by <Icon> and every iconName prop
- Components read config via usePureAdminConfig() hook

PureAdminProvider props:
  config?: Partial<PureAdminConfig>
  shouldHandleShortcuts?: boolean = true
  iconProviders?: IconProvider[]   (ordered; first provider returning markup wins)

Icon providers (exported): fontAwesome(), svgIcons(map), combine(), masked().
Framework affordance icons (close, chevrons, success, danger, ...) resolve built-in
first — no provider needed. Configure providers only for your own icon set:

<script>
  import { PureAdminProvider, fontAwesome } from '@keenmate/svelte-pure-admin';
  let { children } = $props();
</script>

<PureAdminProvider iconProviders={[fontAwesome()]}>
  {@render children()}
</PureAdminProvider>

Then any iconName prop resolves through them (fontAwesome: "save" -> fa-solid fa-save):
<Button iconName="save">Save</Button>

LAYOUT SETUP
-------------
Full admin layout with sidebar, navbar, and content area:

<script>
  import '@keenmate/pure-admin-core/css';
  import {
    PureAdminProvider,
    fontAwesome,
    Layout,
    LayoutInner,
    LayoutContent,
    Navbar,
    Sidebar,
    SidebarItem,
    Main,
    Footer
  } from '@keenmate/svelte-pure-admin';

  let { children } = $props();
  let sidebarOpen = $state(true);
</script>

<PureAdminProvider config={{ app: { name: 'My App' } }} iconProviders={[fontAwesome()]}>
  <Layout>
    <Navbar
      hasBurger={true}
      isBurgerActive={sidebarOpen}
      onburgerclick={() => sidebarOpen = !sidebarOpen}
    />
    <LayoutInner>
      <Sidebar>
        <SidebarItem labelText="Dashboard" href="/" iconName="home" />
        <SidebarItem labelText="Users" href="/users" iconName="users" />
        <SidebarItem labelText="Settings" href="/settings" iconName="gear" />
      </Sidebar>
      <LayoutContent>
        <Main>
          {@render children()}
        </Main>
        <Footer />
      </LayoutContent>
    </LayoutInner>
  </Layout>
</PureAdminProvider>

Key layout components:
- Layout — Outermost wrapper (pa-layout)
- LayoutInner — Inner flex container
- LayoutContent — Content area beside sidebar
- Navbar — Top bar: burger + three zones (start / center / end snippets);
  compose AppHeader / NavMenu / PageHeader inside the zones (see layout.txt)
- Sidebar — Side navigation with collapsible items
- SidebarItem — Navigation link with icon, label, optional submenu
- Main — Main content area
- Footer — Page footer with copyright from config

COMPONENT PATTERN
-----------------
Every component in this library follows the same pattern:

1. Props via $props() with TypeScript interface:

   <script lang="ts">
     interface Props {
       variant?: 'primary' | 'success' | 'danger';
       titleText?: string;
       isDisabled?: boolean;
       onclick?: (event: MouseEvent) => void;
       children?: import('svelte').Snippet;
       header?: import('svelte').Snippet;
     }

     let { variant = 'primary', titleText, isDisabled = false, onclick, children, header }: Props = $props();
   </script>

2. Class building via $derived():

   const classes = $derived(() => {
     const base = ['pa-component'];
     if (variant) base.push(`pa-component--${variant}`);
     if (isDisabled) base.push('pa-component--disabled');
     return base.join(' ');
   });

3. Content via Snippets (not slots):

   <div class={classes()}>
     {#if header}
       <div class="pa-component__header">
         {@render header()}
       </div>
     {/if}
     {@render children?.()}
   </div>

4. Usage with Snippets:

   <Card>
     {#snippet header()}
       <h3>My Title</h3>
     {/snippet}

     <p>Body content goes here as children.</p>

     {#snippet footer()}
       <Button variant="primary">Save</Button>
     {/snippet}
   </Card>

Text vs Snippet props:
- Use *Text props for simple strings: titleText="Welcome"
- Use Snippet props for rich content: {#snippet header()} ... {/snippet}
- Text props are simpler; Snippets allow full markup

SVELTE 5 REQUIREMENTS
---------------------
This library requires Svelte 5. It uses runes exclusively.

Required syntax:
- $props() for component props (NOT export let)
- $state() for reactive state (NOT let with $:)
- $derived() for computed values (NOT $: reactive statements)
- {#snippet} for named content slots (NOT <slot>)
- {@render} to render snippets (NOT <slot>)
- Lowercase event handlers: onclick, onchange, onclose (NOT on:click)

If you see errors about $props, $state, or $derived not being recognized,
ensure your project is using Svelte 5 (check package.json).

COMMON SETUP PATTERNS
---------------------
Minimal (just CSS and a card):
<script>
  import '@keenmate/pure-admin-core/css';
  import { Card } from '@keenmate/svelte-pure-admin';
</script>

<Card titleText="Hello">Content here.</Card>

Full admin dashboard:
<script>
  import '@keenmate/pure-admin-core/css';
  import {
    PureAdminProvider, Layout, LayoutInner, LayoutContent,
    Navbar, Sidebar, SidebarItem, Main, Footer,
    DialogContainer, ToastContainer
  } from '@keenmate/svelte-pure-admin';
  let { children } = $props();
</script>

<PureAdminProvider>
  <Layout>
    <Navbar hasBurger={true} />
    <LayoutInner>
      <Sidebar>
        <SidebarItem labelText="Home" href="/" />
      </Sidebar>
      <LayoutContent>
        <Main>
          {@render children()}
        </Main>
        <Footer />
      </LayoutContent>
    </LayoutInner>
  </Layout>
  <DialogContainer />
  <ToastContainer placement="top-end" />
</PureAdminProvider>

With i18n:
<script>
  import '@keenmate/pure-admin-core/css';
  import { PureAdminProvider } from '@keenmate/svelte-pure-admin';
  let { children } = $props();

  const config = {
    app: { name: 'My App' },
    i18n: {
      locale: 'en',
      fallbackLocale: 'en'
    }
  };
</script>

<PureAdminProvider {config}>
  {@render children()}
</PureAdminProvider>

With theme (theme CSS linked in app.html, e.g. /themes/dark/css/dark.css):
<script>
  import { PureAdminProvider } from '@keenmate/svelte-pure-admin';
  let { children } = $props();
</script>

<PureAdminProvider config={{ ui: { theme: 'dark' } }}>
  {@render children()}
</PureAdminProvider>

CRITICAL REMINDERS
------------------
DO: Import @keenmate/pure-admin-core/css in your root layout
DO: Use Svelte 5 runes ($props, $state, $derived) exclusively
DO: Wrap your app in PureAdminProvider for config context
DO: Use Snippets ({#snippet}, {@render}) for named content areas
DO: Use lowercase event handlers (onclick, onclose, onchange)
DO: Use *Text props for simple strings (titleText, labelText)
DO: Use is*/has*/should* prefix for boolean props
DO: Use the class prop to add custom CSS classes to any component
DO: Import individual components (tree-shakeable)

DO NOT: Use legacy Svelte syntax (export let, <slot>, on:click, $:)
DO NOT: Forget the CSS import (components render unstyled without it)
DO NOT: Write pa-* class names manually (components handle BEM internally)
DO NOT: Use camelCase event handlers (onClick, onChange - wrong)
DO NOT: Skip PureAdminProvider (some components depend on config context)
DO NOT: Import the entire library as a single default export
