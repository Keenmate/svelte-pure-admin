LAYOUT COMPONENTS
=================

CRITICAL: This is a Svelte 5 component library (@keenmate/svelte-pure-admin).
- All components use Svelte 5 runes ($props, $state, $derived)
- Content sections use Snippets ({#snippet}), NOT slots (<slot>)
- BEM class names internally (pa-* components, pc-* shell/grid) - you never write CSS classes manually
- Import from '@keenmate/svelte-pure-admin'

INSTALLATION
------------
npm install @keenmate/svelte-pure-admin

CSS must be imported once in your app (e.g., +layout.svelte):

<script>
  import '@keenmate/pure-admin-core/css';
</script>

LAYOUT STRUCTURE OVERVIEW
-------------------------
The layout system uses a nested hierarchy:

Layout > LayoutInner > Sidebar + LayoutContent > Main + Footer

Every Pure Admin app follows this pattern:

<Layout>
  <Navbar />
  <LayoutInner>
    <Sidebar />
    <LayoutContent>
      <Main>
        ...page content...
      </Main>
      <Footer />
    </LayoutContent>
  </LayoutInner>
</Layout>


COMPLETE LAYOUT SETUP EXAMPLE
------------------------------

<script lang="ts">
  import {
    Layout, LayoutInner, LayoutContent,
    Navbar, AppHeader, NavMenu, NavItem, Sidebar, SidebarItem,
    Main, Footer, Grid, Column, Section
  } from '@keenmate/svelte-pure-admin';
  import { page } from '$app/stores';

  let sidebarCollapsed = $state(false);

  function toggleSidebar() {
    sidebarCollapsed = !sidebarCollapsed;
    document.body.classList.toggle('sidebar-hidden', sidebarCollapsed);
  }
</script>

<Layout>
  <Navbar
    hasBurger={true}
    isBurgerActive={!sidebarCollapsed}
    onburgerclick={toggleSidebar}
  >
    {#snippet start()}
      <AppHeader><h1>My App</h1></AppHeader>
    {/snippet}

    {#snippet end()}
      <NavMenu>
        <NavItem href="/settings">Settings</NavItem>
        <NavItem href="/profile">Profile</NavItem>
      </NavMenu>
    {/snippet}
  </Navbar>

  <LayoutInner>
    <Sidebar>
      <SidebarItem href="/" labelText="Dashboard" isActive={$page.url.pathname === '/'}>
        {#snippet icon()}<i class="fa fa-home"></i>{/snippet}
      </SidebarItem>
      <SidebarItem href="/users" labelText="Users" isActive={$page.url.pathname.startsWith('/users')}>
        {#snippet icon()}<i class="fa fa-users"></i>{/snippet}
      </SidebarItem>
      <SidebarItem labelText="Reports" hasSubmenu={true}>
        {#snippet icon()}<i class="fa fa-chart-bar"></i>{/snippet}
        {#snippet submenu()}
          <SidebarItem href="/reports/sales" labelText="Sales" isActive={$page.url.pathname === '/reports/sales'} />
          <SidebarItem href="/reports/traffic" labelText="Traffic" isActive={$page.url.pathname === '/reports/traffic'} />
        {/snippet}
      </SidebarItem>
    </Sidebar>

    <LayoutContent>
      <Main>
        <Section titleText="Welcome">
          <p>Your page content here.</p>
        </Section>
      </Main>

      <Footer>
        {#snippet start()}
          <p>Copyright 2026 My Company</p>
        {/snippet}
        {#snippet end()}
          <p>v1.0.0</p>
        {/snippet}
      </Footer>
    </LayoutContent>
  </LayoutInner>
</Layout>

NAVBAR
------
Header/navigation bar. Renders <nav class="pc-navbar"> with a fixed burger anchor
plus three degradable zones inside .pc-navbar__inner (the app shell lives in
@keenmate/pure-css, hence the pc- prefix):
  - pc-navbar__burger (fixed anchor — __inner's first child, OUTSIDE the zones)
  - pc-navbar__start  (brand `.pc-app-header` + start nav `.pc-navmenu`)
  - pc-navbar__center (page title `.pc-page-header` + search; flex:1)
  - pc-navbar__end    (end nav `.pc-navmenu`, notifications, profile)

The zones are OPEN containers — Navbar prescribes NO fixed brand / nav / search /
profile slots or ordering. Compose each zone with the content pieces below and wrap
anything responsive in a FitSlot. Navbar only renders the shell + inits the header
engines (fit on .pc-navbar__inner; navbar-dropdown globally).

Props (shell only):
  class?: string              Additional CSS classes for outer <nav>
  innerClass?: string         Additional CSS classes for .pc-navbar__inner
  hasBurger?: boolean         Show the burger toggle (default: false)
  onburgerclick?: () => void  Burger click handler
  isBurgerActive?: boolean    Burger in active X state (default: false)
  start?: Snippet             START zone content (inline-start)
  center?: Snippet            CENTER zone content (flex:1)
  end?: Snippet               END zone content (inline-end)

Content pieces (place inside the zones):
  AppHeader    <div class="pc-app-header"> — app identity. children, or config brand
               (logo + app.name) as a fallback when no children. `class`.
  NavMenu      <nav class="pc-navmenu"><ul> — a nav menu; owns responsive collapse.
               Props: collapse ('menu' | 'sidebar'), moreLabelText, collapseTarget,
               collapseLabelText, collapseIconText, class. Children are NavItems.
  PageHeader   <div class="pc-page-header"> — page-title wrapper. children, class.
  NavItem      one menu item. href, hasDropdown, isActive, navPriority,
               navCollapse="hide", iconText; `dropdown` snippet -> NavDropdown.
  NavDropdown  <ul class="pc-navmenu__dropdown"> submenu. isLevel2, class.
  NavbarSearch search pill that opens the command palette. placeholder, onclick, class.
  NavbarSearchField inline LIVE search box (.pc-navbar-search--field) with its own
               anchored .pa-search-autocomplete dropdown. ONE globalSearch(query) call
               returns a flat SearchResult[]; each row's `group` field is bucketed
               client-side into sections (single round-trip, no fan-out). Props:
               value (bindable), placeholder, globalSearch, onselect, groups
               (SearchGroup[] label/icon/order/limit), debounce, minChars, emptyText,
               shouldRenderHtml (render <mark> highlight).
  NavbarSearchInput type-and-go (.pc-navbar-search--input): a GET <form> that navigates
               to a results page on Enter (no dropdown/palette). Props: action, method,
               name (->query param), value, placeholder.
  ProfileButton profile button. name, onclick, `icon` snippet or iconName.

Search destination + sidebar search (rc15):
  SearchResults page-level results list (.pa-search-results). Props: results
               (SearchResult[]), variant (compact|detailed|grouped|cards), groups,
               shouldRenderHtml, onselect, emptyText. `grouped` buckets by SearchResult.group.
  SidebarSearch sidebar search affordance (.pc-sidebar__search); renders its own
               <li class="pc-sidebar__item">. Trigger mode (onclick -> palette) or
               type-and-go (set `action` -> .pc-sidebar__search--input GET form).
               Props: labelText, onclick, action, method, name, value, placeholder,
               icon (snippet) / iconName.

Minimal navbar (config brand auto-fills AppHeader):

<Navbar>
  {#snippet start()}<AppHeader />{/snippet}
</Navbar>

Navbar composing all three zones:

<Navbar hasBurger onburgerclick={toggleSidebar}>
  {#snippet start()}
    <AppHeader><h1>Admin Panel</h1></AppHeader>
    <NavMenu collapse="sidebar" collapseLabelText="Menu">
      <NavItem href="/dashboard" isActive iconText="D">Dashboard</NavItem>
      <NavItem href="/analytics">Analytics</NavItem>
    </NavMenu>
  {/snippet}

  {#snippet center()}
    <PageHeader><h2>Page Title</h2></PageHeader>
  {/snippet}

  {#snippet end()}
    <NavMenu>
      <NavItem href="/help">Help</NavItem>
    </NavMenu>
    <ProfileButton name="JD" onclick={openProfile} />
  {/snippet}
</Navbar>


NAVBAR FIT (FitSlot / FitStep)
------------------------------
Priority-driven degradation of the whole header row (core fit.js). As the bar
narrows, slots degrade one at a time, LOWEST priority first, until it fits; they
restore as space returns. Pure composition — wrap any header slot in a FitSlot.

FitSlot props:
  strategy?: 'hide' | 'steps' | 'relocate' | 'sidebar'
                                            How the slot yields (default 'hide');
                                            'sidebar' = relocate + target="sidebar"
  priority?: number                         Degrade order — lower degrades first
  tag?: string                              Element to render (default 'span')
  target?: string                           relocate sink: 'sidebar' | 'floating-menu' | custom
  targetSelector?: string                   Destination selector for sinks that need one
  isManaged?: boolean                       Fire pc:fit-relocate but do NO DOM move (you re-render)
  onrelocate?: (detail) => void             detail = { action: 'out' | 'in', target, container }
  class?: string                            Applied to the slot element itself
  sidebarTarget?: string                    Deprecated — use targetSelector

FitStep (only inside a strategy="steps" FitSlot): one ranked variant, widest first.
Auto-numbers itself and hides non-first steps for a correct first paint — no
data-pc-fit-step / pc-fit-hidden to hand-author.

Composed header brand (wordmark shrinks to a monogram; version drops first):

<Navbar hasBurger onburgerclick={toggleSidebar}>
  {#snippet start()}
    <AppHeader>
      <h1>
        <FitSlot strategy="steps" priority={30} class="pc-app-header__name">
          <FitStep>Svelte Pure Admin</FitStep>
          <FitStep>SPA</FitStep>
        </FitSlot>
        <FitSlot priority={10} class="pc-app-header__version">v1.0.0</FitSlot>
      </h1>
    </AppHeader>
  {/snippet}
  {#snippet center()}
    <FitSlot priority={20} tag="div"><PageHeader><h2>Dashboard</h2></PageHeader></FitSlot>
  {/snippet}
</Navbar>


SIDEBAR
-------
Side navigation panel. Renders <aside class="pc-layout__sidebar"> with <nav class="pc-sidebar__nav"><ul>.

Props:
  isIconCollapse?: boolean              Collapse to an icon rail (pc-layout__sidebar--icon-collapse)
  mode?: 'icon-collapse'                Deprecated — use isIconCollapse
  isResizable?: boolean                 Enable drag-to-resize (default: false)
  class?: string                        Additional CSS classes
  children?: Snippet                    SidebarItem / SidebarSection / SidebarDivider / SidebarSearch

Sticky sidebar is the body class pc-layout--sticky, not a Sidebar prop.
Collapsed-rail submenu flyouts are kept inside the viewport automatically.

Resizable sidebar features (core sidebar-resize.js):
  - Drag handle created on the inline-end edge
  - Width saved to localStorage ('sidebar-width'), restored on load
  - Bounds from CSS (--pc-local-sidebar-min-width / --pc-local-sidebar-max-width)
  - Double-click handle to reset

Basic sidebar:

<Sidebar>
  <SidebarItem href="/" labelText="Home" />
  <SidebarItem href="/about" labelText="About" />
</Sidebar>

Resizable sidebar:

<Sidebar isResizable={true}>
  <SidebarItem href="/" labelText="Dashboard" />
</Sidebar>

Icon-collapse mode (shows only icons when collapsed):

<Sidebar isIconCollapse={collapsed}>
  <SidebarItem href="/" labelText="Home">
    {#snippet icon()}<i class="fa fa-home"></i>{/snippet}
  </SidebarItem>
</Sidebar>

To collapse/show sidebar, toggle body class:

document.body.classList.toggle('sidebar-hidden');

SidebarSection (<li class="pc-sidebar__section">): group heading. Props: labelText, class.
SidebarDivider (<li class="pc-sidebar__divider">): separator line. Props: class.

<Sidebar>
  <SidebarSection labelText="Admin" />
  <SidebarItem href="/users" labelText="Users" />
  <SidebarDivider />
  <SidebarItem href="/help" labelText="Help" />
</Sidebar>


SIDEBAR ITEM
-------------
Individual sidebar navigation item. Renders <li class="pc-sidebar__item">.
Supports links, buttons, and collapsible submenus with localStorage persistence.

Props:
  href?: string                       Item URL (renders <a>)
  isActive?: boolean                  Is active/selected (default: false)
  icon?: Snippet                      Icon content
  iconName?: string                   Icon name rendered through <Icon> (the icon snippet wins)
  labelText: string                   Label text (REQUIRED)
  hasSubmenu?: boolean                Has expandable submenu (default: false)
  submenu?: Snippet                   Submenu items
  onclick?: (event: MouseEvent) => void   Click handler
  class?: string                      Additional CSS classes
  shouldKeepIconSpace?: boolean       Keep icon space even without icon (default: true)

When href is not provided and hasSubmenu is false, renders a <button>.
When hasSubmenu is true, renders a toggle <button> with chevron.
Submenu open/close state is saved to localStorage using labelText as key.

Simple link item:

<SidebarItem href="/dashboard" labelText="Dashboard" isActive={$page.url.pathname === '/dashboard'} />

Item with icon:

<SidebarItem href="/users" labelText="Users" isActive={$page.url.pathname.startsWith('/users')}>
  {#snippet icon()}<i class="fa fa-users"></i>{/snippet}
</SidebarItem>

Item with collapsible submenu:

<SidebarItem labelText="Settings" hasSubmenu={true}>
  {#snippet icon()}<i class="fa fa-cog"></i>{/snippet}
  {#snippet submenu()}
    <SidebarItem href="/settings/general" labelText="General" />
    <SidebarItem href="/settings/security" labelText="Security" />
    <SidebarItem href="/settings/notifications" labelText="Notifications" />
  {/snippet}
</SidebarItem>

Button item (no href):

<SidebarItem labelText="Logout" onclick={() => logout()}>
  {#snippet icon()}<i class="fa fa-sign-out"></i>{/snippet}
</SidebarItem>

Active state with SvelteKit page store:

<script>
  import { page } from '$app/stores';
</script>

<SidebarItem href="/users" labelText="Users" isActive={$page.url.pathname.startsWith('/users')}>
  {#snippet icon()}<i class="fa fa-users"></i>{/snippet}
</SidebarItem>

Without icon space (for sub-items that do not need alignment):

<SidebarItem href="/item" labelText="No Icon" shouldKeepIconSpace={false} />

GRID
----
Row container for the column grid system. Renders <div class="pc-row">.
Uses CSS flexbox with modifier classes for alignment, gutters, and gap.

Props:
  isNoGutter?: boolean                        Remove spacing between columns (default: false)
  justify?: 'center' | 'end' | 'between' | 'around'    Horizontal alignment
  align?: 'top' | 'middle' | 'bottom' | 'stretch'   Vertical alignment
  isSameHeight?: boolean                      Force all columns to equal height (default: false)
  gap?: '0' | 'xs' | 'sm' | 'md' | 'base' | 'lg' | 'xl' | '2xl' | number
                                            Gap between items (semantic name or numeric 1-20)
  class?: string                            Additional CSS classes
  style?: string                            Inline styles
  children?: Snippet                        Column components

Basic grid:

<Grid>
  <Column size="50">Left half</Column>
  <Column size="50">Right half</Column>
</Grid>

Three equal columns:

<Grid>
  <Column size="1-3">One</Column>
  <Column size="1-3">Two</Column>
  <Column size="1-3">Three</Column>
</Grid>

Centered content with gap:

<Grid justify="center" gap="md">
  <Column size="1-3">Centered</Column>
</Grid>

No gutters:

<Grid isNoGutter={true}>
  <Column size="50">Flush left</Column>
  <Column size="50">Flush right</Column>
</Grid>

Same-height columns (for card grids):

<Grid isSameHeight={true} gap="lg">
  <Column size="1-3"><Card>Short</Card></Column>
  <Column size="1-3"><Card>Tall card with more content</Card></Column>
  <Column size="1-3"><Card>Medium</Card></Column>
</Grid>

Vertical and horizontal alignment:

<Grid align="middle" justify="between">
  <Column size="30">Short</Column>
  <Column size="30">Tall content here</Column>
</Grid>

Numeric gap (1-20):

<Grid gap={4}>
  <Column size="50">Left</Column>
  <Column size="50">Right</Column>
</Grid>


COLUMN
------
Grid column with responsive breakpoints. Renders <div class="pc-col-*">.

Supports percentage widths (5% increments: 5, 10, 15, ..., 100),
fraction widths (1-2, 1-3, 2-3, 1-4, 3-4, etc.), and auto width.

Props:
  size?: ColumnSize           Base column size
  sm?: ColumnSize             Size at >=576px
  md?: ColumnSize             Size at >=768px
  lg?: ColumnSize             Size at >=992px
  xl?: ColumnSize             Size at >=1200px
  offset?: OffsetSize         Left margin offset (5% increments, 5-95)
  offsetSm?: OffsetSize       Offset at >=576px
  offsetMd?: OffsetSize       Offset at >=768px
  offsetLg?: OffsetSize       Offset at >=992px
  offsetXl?: OffsetSize       Offset at >=1200px
  isNoPadding?: boolean       Drop the column gutter (pc-col--no-padding)
  isGrow?: boolean            flex-grow (pc-col--grow)
  isShrink?: boolean          Allow shrinking below content (pc-col--shrink)
  class?: string              Additional CSS classes
  style?: string              Inline styles
  children?: Snippet          Column content

ColumnSize: '5' | '10' | '15' | ... | '100' | '1-2' | '1-3' | '2-3' | '1-4' | '3-4' |
            '1-5' | '2-5' | '3-5' | '4-5' | '1-6' | '5-6' | '1-12' | '5-12' |
            '7-12' | '11-12' | 'auto'

OffsetSize: '5' | '10' | '15' | ... | '95'

Fixed width columns:

<Grid>
  <Column size="25">25%</Column>
  <Column size="75">75%</Column>
</Grid>

Fraction-based columns:

<Grid>
  <Column size="1-3">One third</Column>
  <Column size="2-3">Two thirds</Column>
</Grid>

Auto-sizing (no size prop):

<Grid>
  <Column>Auto width</Column>
  <Column>Auto width</Column>
</Grid>

FIT CONTAINER
-------------
Arms any horizontal flex row (toolbar, filter bar, card actions) with the fit engine:
children fold, lowest priority first, when the row runs out of width.

Props:
  isAuto?: boolean            Fold EVERY direct child (data-pc-fit-auto) (default: true);
                              false = only children wrapped in FitSlot are managed
  defaultPriority?: number    Priority inherited by untagged children (lower folds first)
  tag?: string                Element tag (default 'div')
  class?: string
  children?: Snippet

<FitContainer class="d-flex gap-2">
  <Button>Save</Button>
  <FitSlot priority={10}><Button>Export</Button></FitSlot>
  <FitSlot strategy="relocate" target="floating-menu" priority={5}>
    <Button>Archive</Button>
  </FitSlot>
</FitContainer>


CONTAINER BREAKPOINT / BREAKER
------------------------------
ContainerBreakpoint maps its OWN inline size to a named mode and passes it to the
children snippet — branches for other modes are never mounted (use for expensive swaps,
e.g. chart vs KPI). Thresholds are rem by default (10px root → 34 = 340px).

ContainerBreakpoint props:
  steps: Record<string, number>   Mode name -> minimum inline size (REQUIRED)
  unit?: 'rem' | 'px'             Threshold unit (default 'rem')
  hysteresis?: number             Dead-band at each threshold (default from config, 1)
  initial?: string                Mode before first measure (default: first key)
  hiddenClass?: string            Class toggled on [data-pc-show] children (default 'd-none')
  tag?: string                    Wrapper tag (default 'div')
  class?: string
  onchange?: (mode, prev) => void Fired on every settled mode change
  children?: Snippet<[{ mode }]>

Breaker props (show/hide but stay MOUNTED, so form state survives):
  mode: string        Current mode from children({ mode })
  show: string        Space-separated modes it appears in, e.g. "comfy wide"
  tag?: string        (default 'div')
  class?: string

<ContainerBreakpoint steps={{ compact: 0, comfy: 34, wide: 64 }}>
  {#snippet children({ mode })}
    {#if mode === 'wide'}
      <RevenueChart {data} />
    {:else}
      <RevenueKpi {data} />
    {/if}
    <Breaker {mode} show="comfy wide"><Field labelText="Phone">555-0100</Field></Breaker>
  {/snippet}
</ContainerBreakpoint>


SPLITTER
--------
Resizable panes (core splitter.js: drag, keyboard, minimize-to-rail, persistence).
Alternate SplitterPane / SplitterGutter children.

Splitter props:
  orientation?: 'horizontal' | 'vertical'  horizontal = side-by-side (default 'horizontal')
  id?: string                 Persist sizes in localStorage (pa-splitter:<id>); also the root id
  step?: number               Keyboard resize step px (default 10)
  railSize?: number           Minimized rail width px (default 40)
  minimizeThreshold?: number  Drag-to-rail snap ratio (default 0.40)
  isMinimizeMirror?: boolean  Flip the rail title 180deg
  onresize?: (detail: { index, pane, size }) => void
  oncollapse? / onexpand?: (detail: { index, pane }) => void
  class?: string; style?: string   (give vertical splitters a height via style)

SplitterPane props: size? ("240px" | "30%"), min?, max?, isMinimizable?, class?, style?
SplitterGutter props: ariaLabel?, class?

<Splitter id="editor" style="height: 400px">
  <SplitterPane size="25%" min="150px" isMinimizable>Sidebar</SplitterPane>
  <SplitterGutter ariaLabel="Resize sidebar" />
  <SplitterPane>Editor</SplitterPane>
</Splitter>

SETTINGS PANEL
--------------
Runtime-configurable settings panel. Provides UI for:
- Theme selection, plus theme mode and colour-variant selectors built from each
  theme's manifest (ThemeOption.colorVariants / modes)
- Layout width (fluid, sm, md, lg, xl, 2xl)
- Sidebar options (behavior: hide / icon-collapse / overlay floating drawer, resizable)
- Display options (compact mode, RTL)
- Profile panel options (avatar, icon-only tabs)
- Font size and family

All settings are persisted to localStorage and applied to DOM automatically.

Props:
  onsettingschange?: (settings: SettingsPanelState) => void
                             Callback when settings change
  availableThemes?: ThemeOption[]
                             Available themes (if empty, theme selector is hidden)
  defaultTheme?: string      Default theme ID

ThemeOption: { id: string; name: string; cssPath: string;
               colorVariants?; modes?; modeCssClass?; variantCssClass? }
               (optional fields come from the theme's theme.json manifest)

Mode / variant changes dispatch a `pa:theme-change` CustomEvent on window
({ kind: 'mode' | 'variant', ... }).

<script lang="ts">
  const themes = [
    { id: 'default', name: 'Default', cssPath: '/themes/default.css' },
    { id: 'dark', name: 'Dark', cssPath: '/themes/dark.css' },
    { id: 'corporate', name: 'Corporate', cssPath: '/themes/corporate.css' }
  ];
</script>

<SettingsPanel
  availableThemes={themes}
  defaultTheme="default"
  onsettingschange={(s) => console.log('Settings changed:', s)}
/>

Without themes (just layout/display settings):

<SettingsPanel />

CRITICAL REMINDERS
------------------
- Layout hierarchy: Layout > LayoutInner > Sidebar + LayoutContent > Main + Footer
- Navbar goes BEFORE LayoutInner, as a direct child of Layout
- Sidebar collapse is controlled via body class: document.body.classList.toggle('sidebar-hidden')
- Container width is set via body class: document.body.classList.add('pc-container-lg')
- SidebarItem requires labelText prop (it is mandatory)
- SidebarItem submenu state is persisted to localStorage automatically
- Sidebar resize width is persisted to localStorage automatically
- Snippets use {#snippet name()} ... {/snippet} syntax, NOT <slot>
- Navbar has only start / center / end zones; compose them with AppHeader, NavMenu (NavItem children), PageHeader, NavbarSearch, ProfileButton
- Footer uses logical directions (start/end) for RTL support
- Grid isSameHeight is useful for card grids where cards have different content lengths
- Column with no size prop and no responsive sizes renders as pc-col (auto width)
- All components accept class prop for custom CSS classes
