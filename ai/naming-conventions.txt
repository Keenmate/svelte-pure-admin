NAMING CONVENTIONS (KEENMATE STANDARD)
=======================================

CRITICAL: This library follows the KeenMate naming methodology across ALL components.
Every prop name is designed to be self-documenting -- the suffix/prefix tells you the type and purpose.
These rules apply to @keenmate/svelte-pure-admin and all KeenMate packages.


BOOLEAN PROPS: is* PREFIX
--------------------------
State flags -- what something IS right now.
Used for component state, visual modifiers, and behavior toggles.

  isGhost          -- Card has no background/border/shadow
  isStat           -- Card uses stat styling
  isStriped        -- Table/Fields has alternating row backgrounds
  isBordered       -- Table/Fields has bottom border separators
  isCompact        -- Tighter spacing (Table, BarList, Heatmap, ButtonGroup)
  isHorizontal     -- Label start, control end (FormGroup, FormField)
  isOpen           -- Overlay open state, bindable (Modal, SlidePanel, Popconfirm, ...)
  isVisible        -- Whole block rendered or not (Toast, FormErrorSummary)
  isActive         -- Active item (TabItem, TabPanel, SidebarItem, ...)
  isTouched        -- Field was touched (Input, Select, FormField, ...)
  isDisabled       -- Disabled (emits the native disabled attribute)
  isReadonly / isRequired / isChecked / isMultiple -- native boolean attributes, same rule
  isFilled         -- Subtle background panel (Fields)
  isScrollable     -- Scrollable body content (Modal, TableCard)
  isStatic         -- Prevents closing via ESC/backdrop (Modal)
  isOutline        -- Outline style (Button)
  isBlock          -- Full width (Button)
  isIconOnly       -- No text, icon only (Button)
  isLoading        -- Loading state (Button, i18n service)
  isRipple         -- Ripple effect on click (Button)
  isPill           -- Pill shape (Badge)
  isRounded        -- Rounded corners (Progress, StackedBar)
  isAnimated       -- Animated stripes (Progress)
  isNegative       -- Red, right-aligned (DataBar)
  isZones          -- Multi-zone green/yellow/red (Gauge)
  isPlain          -- Plain/unstyled variant (Table, TableCard)
  isResponsive     -- Responsive table with horizontal scrolling
  isResponsiveGrid -- Collapses to cards on mobile
  isEllipsisStart  -- Ellipsis at start of text (Badge)
  isInteractive    -- Renders as button element (CompositeBadge)
  isFilled         -- Filled marker instead of outline (TimelineItem)
  isDateHeader     -- Is this a date header (TimelineItem)
  isTotal          -- Bold total row (DotLeadersItem)
  isBold           -- Bold value (PropCardRow)

Examples in component code:

  <Table isStriped isCompact>...</Table>
  <Card isGhost isStat>...</Card>
  <Button isOutline isBlock isLoading>...</Button>
  <Modal isScrollable isStatic>...</Modal>
  <Fields layout="horizontal" isBordered isStriped>...</Fields>
  <Progress isRounded isStriped isAnimated value={75} />


BOOLEAN PROPS: has* PREFIX
---------------------------
Feature flags -- whether something HAS a feature enabled.

  hasPadding         -- Body has padding (Card, set false to remove)
  hasBorder          -- Show left border (Fields, set false to remove)
  hasInlineTabs      -- Pill-style buttons inside card header
  hasContainerQuery  -- Wrap in container for CSS container query
  hasAvatar          -- Item shows an avatar image
  hasClose           -- Show close button (Modal)
  hasProgress        -- Show progress bar (Toast)
  hasInfo            -- Show page info (Pager)
  hasHeader          -- Show header row (KpiStrip, default true)

Examples:

  <Card hasPadding={false}>...</Card>
  <Fields hasBorder={false} hasContainerQuery>...</Fields>


BOOLEAN PROPS: should* PREFIX
-------------------------------
Behavior flags -- what the component SHOULD do.
Controls behavior, not appearance.

  shouldCloseOnEscape    -- Close on Escape key (Modal)
  shouldHandleShortcuts  -- Handle the global keyboard shortcuts (PureAdminProvider)
  shouldWrapHeader       -- Let the card description wrap onto its own line (Card)
  shouldCloseOnBackdrop  -- Close on backdrop click (Modal)
  shouldRenderHtml       -- Render result text as HTML (NavbarSearchField, SearchResults)

Showing a part is has* (hasClose, hasProgress), not shouldShow*.

Examples:

  <Modal hasClose={false} shouldCloseOnEscape={false}>...</Modal>
  <Toast hasProgress duration={5000} titleText="Saved" messageText="Done" />


TEXT CONTENT PROPS: *Text SUFFIX
---------------------------------
String props that provide text content to display.
The suffix tells you this is a displayable string, not a behavior flag.

  titleText        -- Card title, Modal title, Toast title
  subtitleText     -- Legacy Card subtitle (.pa-card__meta); prefer descriptionText
  descriptionText  -- Description (Card, inline with title)
  labelText        -- Field label, Stat label, Progress label
  valueText        -- Field value, Progress value display
  messageText      -- Toast message, Alert message
  headingText      -- Heading content
  symbolText       -- Symbol display (Stat square layout)
  changeText       -- Change text like "+12.5%" (Stat)
  timeText         -- Time/date text
  minText          -- Minimum label (Gauge)
  maxText          -- Maximum label (Gauge)
  copyHintText     -- Hint for copy mode (Field)
  copiedText       -- Feedback text after copy (Field)
  confirmText      -- Confirm button text (Dialog)
  cancelText       -- Cancel button text (Dialog)
  okText           -- OK button text (Dialog)
  buttonText       -- Button/count text (CompositeBadge)
  unitText / prefixText -- KPI value unit / prefix
  countText        -- Count text (LoadMore)

Examples:

  <Card titleText="User Profile" descriptionText="Manage your account">...</Card>
  <Stat labelText="Revenue" number="$45K" changeText="+8.3%" />
  <Toast titleText="Success" messageText="Changes saved successfully" variant="success" />
  <Field labelText="Email" valueText="john@example.com" />
  <Progress labelText="Upload" valueText="75%" value={75} />


EVENT HANDLERS: on* PREFIX (LOWERCASE)
---------------------------------------
Fire-and-forget event notifications. The return value is NOT used by the component.
Svelte 5 uses native DOM event syntax: all lowercase, no camelCase.

DOM event forwarders (standard HTML events):
  onclick       -- Click handler
  onchange      -- Value change handler
  oninput       -- Input handler (fires on every keystroke)
  onblur        -- Focus lost handler
  onfocus       -- Focus gained handler
  onkeydown     -- Key press handler

Custom component events (fire-and-forget):
  onclose       -- Called when Modal/Toast/Panel closes
  onconfirm     -- Called when user confirms (Dialog, Popconfirm)
  oncancel      -- Called when user cancels
  ondismiss     -- Called when notification is dismissed
  oncopy        -- Called after successful clipboard copy (Field)
  onpagechange  -- Called when page changes (Pager)
  onburgerclick -- Called when burger menu is clicked (Navbar)
  onglobalselect -- Called when global search result selected (CommandPalette)

WRONG (do NOT use camelCase for handlers):
  onClick       -- WRONG
  onChange      -- WRONG
  onClose       -- WRONG

Examples:

  <Button onclick={() => console.log('clicked')}>Click Me</Button>
  <Modal bind:isOpen={isOpen} onclose={() => console.log('closed')}>...</Modal>
  <Input bind:value={email} oninput={(e) => validate(e)} onblur={handleBlur} />
  <Field labelText="ID" valueText="abc-123" copyMode="btn" oncopy={(v) => log(v)} />


CALLBACKS WITH RETURN VALUE: *Callback SUFFIX
-----------------------------------------------
Only used when the return value controls component behavior.
The component READS the return value to decide what to do.

  beforeCloseCallback  -- Return false to PREVENT closing (Modal)
  copyValueCallback    -- Returns string for clipboard (Field)
  get*Callback         -- Returns data for rendering

WRONG:
  closeCallback        -- Don't use for fire-and-forget (use onclose)
  confirmCallback      -- Don't use for fire-and-forget (use onconfirm)

Examples:

  <Modal
    bind:isOpen={isOpen}
    beforeCloseCallback={() => {
      if (hasUnsavedChanges) {
        return false; // Prevent close!
      }
      // Allow close (return void/true)
    }}
    onclose={() => console.log('closed')} // Fire-and-forget notification
  >
    ...
  </Modal>

  <Field
    labelText="Token"
    valueText="***masked***"
    copyMode="btn"
    copyValueCallback={() => getActualToken()} // Returns the real value to copy
    oncopy={(v) => audit.log('token copied')}   // Fire-and-forget notification
  />


CSS CLASS PROPS: class AND *Class SUFFIX
------------------------------------------
String props for passing CSS class names.

  class          -- Standard additional CSS classes (every component has this)
  headerClass    -- Extra classes for header element (Card)
  bodyClass      -- Extra classes for body element (Card, Modal)
  footerClass    -- Extra classes for footer element (Modal)
  labelClass     -- Extra classes for label element (BandedRow)

The standard 'class' prop is aliased internally:
  let { class: className = '' }: Props = $props();

Examples:

  <Card class="mb-4" headerClass="bg-primary text-white">...</Card>
  <Modal bodyClass="p-0" footerClass="justify-end">...</Modal>
  <Button class="wr-5 minwr-5">Fixed Width</Button>


NATIVE HTML ATTRIBUTES
----------------------
BOOLEAN native attributes follow the is*/has*/should* rule like every other
boolean — the component emits the native attribute internally:

  isDisabled     -- emits disabled (Button, Input, Select, ...)
  isReadonly     -- emits readonly (Input, Textarea)
  isRequired     -- emits required (Input, Select, Checkbox, ...) -- on the CONTROL;
                    FormLabel / FormField / FormGroup have no required prop
  isChecked      -- emits checked (Checkbox; bind:isChecked)
  isMultiple     -- emits multiple (Select, FileInput)

Non-boolean native attributes keep their HTML names:

  placeholder    -- Not placeholderText (Input, Textarea, Select)
  id             -- Element ID
  name           -- Form field name
  type           -- Button type, Input type
  href           -- Link URL (Button as anchor)
  target         -- Link target (Button as anchor)

Examples:

  <Button isDisabled>Can't Click</Button>
  <Input placeholder="Enter email" isRequired isDisabled={!canEdit} />
  <Select name="country" id="country-select">...</Select>


VISUAL/STRUCTURAL PROPS: variant, size, type
----------------------------------------------
Standard pattern props for visual appearance:

  variant        -- Role colour (primary, success, danger, warning, info, etc.) — never a shape or layout
  size           -- Size variant (xs, sm, lg, xl)
  type           -- Predefined design (Tabs pills/boxed, Loader dots/ring, OrderedList roman) or native type
  mode           -- Which behaviour (copyMode btn/click/hover, titleTooltipMode overflow/always)
  layout         -- Arrangement of children (Stat, KpiBento, Fields, CheckboxGroup)
  density        -- Spacing (compact / relaxed: Fields, BasicList)
  themeColor     -- Theme color slot (1-9) for numbered color schemes
  placement      -- Where a floating / overlay element sits (top, bottom, start, end, top-end, center …)
  <part>Placement -- Where one part sits (labelPlacement, iconPlacement, infoPlacement)

Layout props are named after the CSS property they drive:
  justify        -- justify-content (Grid, Button, Tabs, Pager, LoadMore)
  align          -- align-items (Grid, ButtonGroup, DescTable/Banded "center")
  textAlign      -- text-align (Paragraph, Heading, Popover; labelTextAlign / valueTextAlign)
  side           -- not a CSS name on purpose (Timeline: all items on one side)
  position       -- only for a real coordinate/length (KPI gauge tick position)

Examples:

  <Button variant="primary" size="lg">Big Button</Button>
  <Badge variant="success" size="sm" isPill>Active</Badge>
  <Toast variant="danger" titleText="Error" messageText="Failed" />
  <Fields themeColor={3} cols={2} layout="horizontal" density="compact">...</Fields>
  <Tabs type="pills" justify="center">...</Tabs>
  <ToastContainer placement="top-end" />


SNIPPET PROPS (NAMED SLOTS)
-----------------------------
Svelte 5 Snippet type for complex content sections:

  children       -- Main body content (default slot replacement)
  header         -- Header section content
  footer         -- Footer section content
  icon           -- Icon content
  title          -- Rich title content (alternative to titleText)
  description    -- Rich description content (alternative to descriptionText)
  actions        -- The single actions area (Alert, Toast, DetailPanel, FilterCard, TableCard)
  headerActions / footerActions -- Card's two actions areas (+ headerActionsCollapsed fallback)
  tabs           -- Tab content area
  titleIcon      -- Icon rendered before title (Card; titleIconName = by name)
  label          -- Rich label content (Field, Checkbox, Radio; alternative to labelText)
  heading        -- Rich heading (Alert, Callout; alternative to headingText)
  meta           -- Rich meta content (ListItem; alternative to metaText)

The bare name is the rich snippet; the plain-text form is *Text (titleText /
title). Icons follow the same split: iconName (string, rendered through <Icon>
so icon providers resolve it) vs icon (rich snippet, wins when both are set).

Type declaration in component:
  header?: import('svelte').Snippet;
  children?: import('svelte').Snippet;


MEMBER PROPS: *Member SUFFIX
------------------------------
Property mappings for data binding. Indicates which field in a data object to use.
Not commonly used in Pure Admin (no complex data binding), but follows KeenMate pattern.

  idMember              -- Which field contains the ID
  displayValueMember    -- Which field to display as text
  searchValueMember     -- Which field to search against

Example (from web-multiselect, same methodology):
  <web-multiselect value-member="id" display-value-member="name" />


TIMEOUT PROPS: *Timeout SUFFIX
-------------------------------
Time duration values, always in milliseconds.

  duration             -- Auto-dismiss duration (Toast)
  timeout              -- Request timeout (RPC transports)

BENEFITS OF THIS METHODOLOGY
------------------------------
1. Self-documenting code -- Prop name tells you the type and purpose
2. No ambiguity -- is* = boolean, *Text = string, on* = event, *Callback = returns value
3. Better IntelliSense -- Related props group together alphabetically
4. Consistency -- Same patterns across all KeenMate packages
5. Easier maintenance -- New developers understand prop purpose immediately


CRITICAL REMINDERS
-------------------
- is* for state booleans: isStriped, isCompact, isGhost, isLoading
- has* for feature presence: hasPadding, hasBorder, hasContainerQuery, hasClose, hasProgress
- should* for behavior flags: shouldCloseOnEscape, shouldHandleShortcuts
- *Text for display strings: titleText, labelText, messageText
- on* (lowercase!) for events: onclick, onclose, onconfirm
- *Callback only when return value matters: beforeCloseCallback, copyValueCallback
- ALL booleans use is*/has*/should*, native ones too: isDisabled, isReadonly, isRequired, isChecked
- Keep non-boolean native attrs as-is: placeholder, name, id, type, href
- iconName (string via <Icon>) vs icon (rich snippet)
- type = predefined design, mode = behaviour, layout = arrangement, density = compact|relaxed spacing, style = inline CSS only
- variant = role colour, themeColor = 1-9 palette slot
- Layout props use CSS names: justify, align, textAlign; placement / <part>Placement for position
- Overlays bind isOpen; rendered-or-not blocks use isVisible
- Use start/end not left/right (RTL support, since v1.4.0/v1.5.0)
- Tooltip / Popconfirm / Popover placement is logical too: top | bottom | start | end
