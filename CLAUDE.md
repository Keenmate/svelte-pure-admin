# @keenmate/svelte-pure-admin — Claude Notes

Svelte 5 component library wrapping the Pure Admin CSS framework (`@keenmate/pure-admin-core`) into reusable, type-safe components. Every component must mirror the HTML structure from the core framework's snippet library.

**Stack:** Svelte 5 (runes) · SvelteKit 2.x library mode · TypeScript · Vite · peers `@keenmate/pure-admin-core` `^3.3.0-rc07` + `@keenmate/pure-css` `^2.0.0-rc02` (npm workspaces: `packages/svelte-pure-admin` = the library, `docs` = the demo site)

## Core rules

1. **Snippet-driven** — read the corresponding `.html` snippet (or SCSS source for data-display / data-viz) before writing any component. Never guess HTML structure or class names.
2. **Svelte 5 runes only** — `$props()`, `$state()`, `$derived()`. No `export let`, no `$:`, no `<slot>`. See [guides/svelte5-patterns.md](docs/guides/svelte5-patterns.md).
3. **BEM class names** — `pa-[block]__[element]--[modifier]`, exactly as in snippets.
4. **TypeScript Props interface** — every component declares its props with an `interface Props`.
5. **Children as snippets** — `{#snippet}` blocks via `import('svelte').Snippet`, not `<slot>`.
6. **`class?: string` prop** — always accept custom classes.
7. **Logical directions** — `start`/`end`, never `left`/`right` (RTL support). Tooltip + Popconfirm use logical classes in core ≥ v2.5.0.
8. **KeenMate naming (same names as keen-pure-admin, camelCase vs snake_case)** — `on*` for fire-and-forget events, `*Callback` only when the return value is used. Every boolean — native ones too (`isDisabled`, `isReadonly`, `isRequired`, `isChecked`, `isMultiple`) — is `is*` (state; overlays use `isOpen`), `has*` (optional part shown; default-on parts are `has*={false}`, never `no*`/`show*`) or `should*` (behaviour). Plain string = `*Text`, rich snippet = bare name (`titleText` / `title`); icon by name = `iconName` (rendered via `<Icon>`) beside the `icon` snippet. `variant` = role colour, `themeColor` = slot 1–9, `type` = predefined design, `mode` = behaviour, `layout` = arrangement, `density` = spacing, `<part>Placement` = where a part sits; `style` is only ever the inline CSS string. Authority: [ai/naming-conventions.txt](ai/naming-conventions.txt) + `../pure-admin/packages/core/fidelity/NAMING.md` (enforced by `npm run fidelity:naming -w @keenmate/pure-admin-core`).
9. **Test against original** — compare with pure-admin demo (port 3000) for visual parity, and against core's golden markup via the fidelity harness (below).

## Demo philosophy — the docs exercise components, not raw markup

The docs site (`docs/`) is not just a showroom — it is how we **prove the component
library is complete and correct**. So:

1. **Build every demo page out of library components.** Only drop to raw `pa-*`
   HTML when there is genuinely no component for that thing — and treat that as a
   signal that a component is probably **missing** and should be added.
2. **A demo page core/keen have but svelte lacks is a two-step job:** first add the
   component(s) (standard naming + structure, mirroring the core snippet / the keen
   wrapper's API), *then* compose the page from them. Never paste the core snippet's
   HTML into a page as a shortcut — that hides the gap instead of closing it.
3. **`svelte-check` is the guardrail that makes this work.** When a page may only use
   components + their typed props, the type-checker rejects invented classes, wrong
   prop names, and nonexistent variants before they ship. Hand-authored
   `class="pa-…"` strings have no such safety net and silently drift from core.

(Same reasoning drives keen's demo + `mix compile`; this is a shared ecosystem rule.)

## Class-vs-prop rule

When a demo/consumer passes a CSS class to a library component, decide prop-vs-`class=` by one litmus: **does `.pa-<thisBlock>`'s own CSS key off that class?**

1. **Own-block modifier or block-hooked behavior → must be a prop.** `pa-<thisBlock>--*` (`pa-btn--primary` → `variant`, `pa-btn--xs` → `size`), a `pa-<thisBlock>__<element>` used as a *state* (`pa-input-group__button` → `isInputGroupButton`), or a generic utility the block's CSS specifically reacts to (`text-truncate` on `.pa-btn` → `shouldTruncateText`). If a prop exists, passing the class is a **BYPASS bug** — use the prop. If none exists, it's a **MISSING PROP** — add one.
2. **Generic framework utility → stays as `class=`.** Spacing (`m*`/`p*`/`gap-*`), sizing (`wr-*`/`minwr-*`/`maxwr-*`/`w-*`), `ms-auto`, flex/display, text color/align. These are orthogonal to any one component — that's what the `class?: string` passthrough (rule 6) is for. **An established utility convention overrides "make it a prop":** width on `Button` stays `wr-*` because core removed `pa-btn--w-*` in rc04.
3. **Foreign-block class → stays as `class=`.** A class owned by a *different* component/page (`pa-comparison-table__copy` on a `Button`). The component must not know about it.
4. **Naming:** boolean props are `is*` / `has*` / `should*` (rule 8). If a prop only works with a companion utility (truncate needs a fixed width), document that dependency in the prop's doc comment.

`Button` was swept against this (`shouldTruncateText` added for `text-truncate`; `isInputGroupButton` bypasses fixed in docs). Remaining components are not yet swept.

Core is the oracle: `../pure-admin/packages/core/fidelity/` holds neutral fixtures + golden markup; this repo's `scripts/fidelity/<component>.map.json` maps each neutral feature to our prop, and `scripts/fidelity/dump.mjs` SSR-renders the component (via vite) into `svelte-<component>.dump.json` (gitignored). Composed scenarios live in `scripts/fidelity/_compose/`. New mapped components must be added to the `REGISTRY` in `dump.mjs`.

- Renaming a prop means updating its `.map.json` too — otherwise coverage goes red. See `../pure-admin/packages/core/fidelity/README.md`.

## Theme management (docs site)

Docs themes are managed by the **`npx @keenmate/pureadmin` CLI** — run `npx @keenmate/pureadmin --llm` for the authoritative reference. Do **not** reverse-engineer the theme loader; use the CLI + config files.

Three config files live in the **project root** (not `docs/`), modelled on `package.json`:

- `pureadmin.json` — committed declarations: `themesDir` (`docs/static/themes`) + the theme list (remote-sourced by default). Hand-edited; never touched by automated commands.
- `pureadmin.lock.json` — committed, tool-managed resolutions (version / content_sha / source per theme).
- `.pureadmin.json` — **gitignored, per-developer** overrides. Local theme `path` overrides go here.

**Load themes from the local `../pure-admin-themes` repo** (built at the current core version): add a `path` per theme to `.pureadmin.json` — `{ "themes": { "audi": { "path": "../pure-admin-themes/audi" }, … } }` (relative to project root) — then `npx @keenmate/pureadmin themes install`. Install re-copies `--path` themes from disk each run (no network) and does **not** pollute the committed lock (reports `override; lock=registry vX`). `docs/static/themes/` is gitignored.

**Manifest-driven theme selectors.** `SettingsPanel`'s Theme Mode and Color Variant selectors are derived from each theme's `theme.json`, not hardcoded — mirroring pure-admin's demo panel. `ThemeOption` carries the manifest's `colorVariants` / `modes` / `modeCssClass` / `variantCssClass` alongside `id`/`name`/`cssPath`; `internal/theme-manifest.ts` normalises the two schemas in the wild (current: `colorVariants` array with per-variant `modes`; legacy: `colorVariants.supported` + top-level `modes.supported`). Consequences: a single-mode theme (dracula, one-dark, …) hides the Mode selector and pins that mode; "Auto (System)" appears only when the theme has both light and dark; a multi-variant theme (`dark` → blue/green/red, `ayu`, `gruvbox`, `tokyo-night`) gets a Color Variant selector applying `pa-color-<id>` to `<body>` (all variants share one CSS file — the class is the switch). Mode/variant classes come from the manifest's patterns, not a hardcoded `pc-mode-{mode}`. Changing either fires `pa:theme-change` on `window` **and** `theme:change` on the core bus, so CSS-var snapshotters (charts, canvas, SVG) can re-read. Auto mode subscribes to core's `colorscheme:change` (`window.pureAdmin.colorScheme` is the single OS-preference watcher) and only opens its own `matchMedia` when core JS isn't loaded. A `ThemeOption` with just `id`/`name`/`cssPath` still works — the panel falls back to the old light/dark/auto list. **Panel option set (synced to demo):** the panel also carries **Search Box** placement (`body[data-search-position]` = `''`|`navbar-inline`|`navbar-compact`|`sidebar`|`navbar-typeahead`|`sidebar-typeahead`; the host reveals its own entry point off the `onsettingschange` state / body attr, and the panel calls `navFit.relayoutAll()` since a trigger changing alters header content) and **Command Palette** size (`pa-command-palette--sm|lg|xl` on `#commandPalette`; `''` = 608px default). The standalone Sidebar **"Collapsed"** checkbox was **removed** — full hide now lives in Sidebar Behavior → "Hide Completely". Mirroring pure-admin's `settings-panel.js`, `body.sidebar-hidden` is flipped **only in the behavior-select `onchange` handler**, never on load or in `applySettings`/`saveSettings` — the runtime shown/hidden state is owned by the host burger + the pre-hydration script (docs `app.html` restores the stored value), so the panel re-forcing it on mount would re-hide the sidebar on every reload. `docs/src/app.html` applies the stored mode + `color-variant` classes pre-hydration and, with **no** stored mode, applies none — the theme's `:root` default is its manifest default, so forcing `light` would flash on dark-first themes.

**Version-coupling gotcha:** a theme's CSS (`css/<id>.css` or `dist/<id>.css`) is **compiled CSS that bundles pure-admin-core + theme overrides**. So the docs is *styled* by whichever core version is baked into the active theme — independent of the component-library / core-JS version. Symptom: themes locked at an older core (e.g. 2.7.0) lack newer core CSS (e.g. 2.9.0 Stat fit-mode: `data-pa-stat-fit` / `pa-stat__slot` / `pa-stat__group`), so JS-driven features render then collapse (the JS restructures the DOM but the CSS has no rules for it). Fix: install themes built at the matching core version. `+layout.server.ts` `resolveCssRelative()` probes `css/<id>.css` → `dist/<id>.css` → manifest `file`, so both packaged and local-`dist` layouts resolve.

## Workflow for a new / updated component

1. Read the snippet (or SCSS source).
2. Identify HTML structure, class patterns, variants, modifiers.
3. Create / update `src/lib/<category>/<ComponentName>.svelte` per the standard template.
4. Add Props interface with full TS types (names per rule 8).
5. Export from `src/lib/index.ts`.
6. Add / update the demo showcase (built from components — see Demo philosophy) and the matching `ai/*.txt` reference.
7. Add / update `scripts/fidelity/<component>.map.json` and run `npm run fidelity`.
8. `npm run check` (or `check:lib` / `check:docs`) — svelte-check over library + docs.
9. `npm run dev` (docs, port 18800; `make dev` also installs themes first) → compare visually with the pure-admin demo (port 3000).

Backward compatible; mirrors core's rc06 opt-out in `split-button.js` — so `data-pa-keep-open` is one convention across both our Svelte-native `SplitButton` and raw-core overflow/split markup.

Our `Button` `justify` prop maps to the `--justify-*` modifiers.

### Thin JS-wrapper components (core v2.9.0-rc)

Since core 2.9.0-rc04 the framework ships interactive behaviours as IIFEs under `@keenmate/pure-admin-core/js/*` (each attaches a `window.Pa*` / `window.pureAdmin.*` API and auto-inits on `DOMContentLoaded`); the app-shell engines (navbar dropdown, fit, container-breakpoint, sidebar resize/flyout) now come from `@keenmate/pure-css/js/*` instead (see below). These wrappers render the BEM markup and drive that JS:

- **Splitter** (`layout/Splitter.svelte` + `SplitterPane` + `SplitterGutter`) → `js/splitter.js` / `window.PaSplitter`. Place panes with a `<SplitterGutter>` between each pair (mirrors the snippet's alternation). Root events `pa-splitter:resize|collapse|expand` → `onresize` / `oncollapse` / `onexpand` callbacks.
- **RangeGroup** (`forms/RangeGroup.svelte`) → `js/range-group.js` / `window.PaRangeGroup`. Data-driven via a `rows` prop; events `pa-range-group:change|apply|reset` → callbacks with the `values` payload. Needs `window.FloatingUIDOM` (same as SplitButton).
- **Card actions-overflow** — `Card` props `isActionsOverflow` / `actionsOverflowFrom` add `.pa-card__actions--overflow` and init `js/overflow.js` (`window.PaOverflow` / back-compat alias `window.PaCardActionsOverflow`). Needs `window.FloatingUIDOM`. Same primitive as the standalone `.pa-overflow` toolbar (see Known upstream gaps); uses `data-pa-actions-priority` / `data-pa-actions-overflow-from`.
- **Stat fit-mode** — `Stat` props `isFit` / `contextText` add `data-pa-stat-fit` and init `js/pa-stat-fit.js` (`window.PaStatFit`), re-fitting on `number` change.
- **Navbar zone schema (`start` / `center` / `end`)** — `layout/Navbar.svelte` mirrors core's universal navbar: a fixed burger + three **open** zones inside `.pc-navbar__inner`. Navbar renders only the shell + inits the fit/dropdown engines; it has **no** brand/nav/search/profile snippets (those opinionated snippets were removed). Compose each zone from `AppHeader` (`layout/AppHeader.svelte`, `.pc-app-header`; children or config-brand fallback), `NavMenu` (see below), `PageHeader` (`layout/PageHeader.svelte`, `.pc-page-header`), `NavItem` / `NavDropdown` / `NavbarSearch` / `ProfileButton`, and wrap anything responsive in a `FitSlot`. Burger via `hasBurger` / `onburgerclick` / `isBurgerActive`.
- **NavMenu responsive collapse** (`navigation/NavMenu.svelte` prop `collapse`) → the one Fit engine's nav path (`@keenmate/pure-css/js/fit.js`, `window.pureAdmin.components.fit.initNav`; the old `navbar-collapse.js` / `window.PaNavCollapse` is gone). `NavMenu` renders `<nav class="pc-navmenu"><ul>` and self-inits on mount. Adds `data-pc-fit-nav` (`menu` | `sidebar`) + config attrs (`moreLabelText` / `collapseTarget` / `collapseLabelText` / `collapseIconText`); only a menu in the **start** zone is shrinkable (core CSS makes only `.pc-navbar__start` shrink). Per-item config lives on `NavItem` (`navPriority` / `navCollapse="hide"` / `iconText`).
- **Navbar touch dropdowns** — `Navbar` loads `@keenmate/pure-css/js/navbar-dropdown.js` (`window.PaNavDropdown`) on mount automatically (no opt-in); first-tap-opens / second-tap-navigates on `(hover: none)`. The module attaches global click/keydown listeners at eval; `init(scope)` only re-applies ARIA.
- **Navbar Fit** (core rc12) — `Navbar` loads `@keenmate/pure-css/js/fit.js` (`loadCoreJs('navbar-fit')`; `window.pureAdmin.components.fit`, alias `navFit`) on mount and inits it on `.pc-navbar__inner`. Priority-driven degradation of the *whole* header (vs `NavMenu`'s `collapse`, which only folds nav items): every slot with `data-pc-fit` (`hide` | `steps` | `sidebar` | `relocate`) + `data-pc-fit-priority` degrades lowest-first until the row fits, then restores. The engine init is the **one non-declarative piece** Navbar owns; **which** slots degrade is pure composition via **`FitSlot` / `FitStep`** — nothing fit-aware is baked into Navbar (the earlier `isTitleFit` / `NavbarSearch.fitPriority` convenience props were removed in favour of composition). `FitSlot` renders *the* measured element (`strategy` · `priority` · `class` · `tag`); a `strategy="steps"` FitSlot holds a `FitStep` ladder (widest-first) and `FitStep` **auto-derives** each `data-pc-fit-step` index (via a `fit-steps-context.ts` counter) and stamps `pc-fit-hidden` on non-first steps for a correct first paint — so authors never hand-number steps. Core's `init` no-ops without `[data-pc-fit]` slots, so a header with no `FitSlot` never degrades. **Relocate + sinks (core rc17):** `strategy="relocate"` moves the slot OUT of the row into a named **sink** (`target` → `data-pc-fit-target`: built-ins `"sidebar"` / `"floating-menu"`, or `registerSink(name,{out,in})`); `targetSelector` → `data-pc-fit-target-selector` for sinks needing a destination; `isManaged` → `data-pc-fit-managed` (hands-off — fit fires but moves no node, you re-render the block in its new home from state); `onrelocate` subscribes to the cancelable `pc:fit-relocate` event (`detail = {action:'out'|'in', target, container}`). `strategy="sidebar"` is core's sugar for relocate + target=sidebar (kept). The old `sidebarTarget` prop now maps onto `data-pc-fit-target-selector` (core dropped `data-pc-fit-sidebar-target` when the sink registry landed). **`FitContainer`** gains `isAuto` (default `true` → `data-pc-fit-auto` folds every child); set `isAuto={false}` to arm the engine on a row but manage only its declared `[data-pc-fit]` slots (e.g. one relocating slot beside fixed content). Both are demoed on the docs **Responsivity — how it works** (`/layout/responsivity`) page's live relocate-to-flyout bar; **Fit to Size** (`/layout/container-breakpoint`) covers steps/CSS-container/ContainerBreakpoint. **Version-coupling:** the toggled `.pc-fit-hidden` (`display:none !important`) is rc12 CSS — a theme built at older core runs the JS but won't hide degraded slots.
- **Navbar structure + naming (rc13 / rc14)** — the burger is a **fixed anchor sibling** of the three zones (first child of `.pc-navbar__inner`, NOT inside `.pc-navbar__start`), since it carries no `data-pc-fit` and must sit outside the measured zones (rc13). rc14 dropped the legacy `pa-header__*` block wholesale (no aliases; legacy markup gets zero styling). These shell blocks have since moved to the pure-css shell layer, so they are **`pc-*`, not `pa-*`**: structure is **`pc-navbar__*`** (`__burger` / `__start` / `__center` / `__end` / `__profile-btn` / `__profile-name`), app identity is **`pc-app-header`** (`__name` / `__version`), the page title is **`pc-page-header`**, and the menu is its own **`pc-navmenu`** block (`__item` / `__link` / `__dropdown` + `--active` / `--has-dropdown` / `--level2`; the `--start`/`--end` nav modifiers are gone — side is decided by the zone). CSS/SCSS tokens renamed `--pc-header-*` → `--pc-navbar-*` (foundation `@keenmate/pure-css` ≥ `^1.0.0-rc03`) — themes must be rebuilt at rc14.
- **Sidebar resize** (`layout/Sidebar.svelte` prop `isResizable`) → `@keenmate/pure-css/js/sidebar-resize.js` / `window.pureAdmin.components.sidebarResize`. Renders `.pc-layout__sidebar--resizable` (the whole sidebar block is now `pc-*` — foundation/shell layer; `pa-sidebar*` = 0 in dist) and inits the module on mount; core creates + binds the `.pc-sidebar-resize` handle itself (so we render **no** handle — core's `init` reuses an existing one WITHOUT re-binding). Drag flags `body.pc-sidebar-resized` (missing this was why the old hand-rolled handle looked dead in the tablet band); bounds/persistence come from core. **`Sidebar` also has a reactive `isIconCollapse` prop** → `pc-layout__sidebar--icon-collapse` (the only real sidebar-element modifier; the former `mode="sticky"` was a phantom — sticky is body-level `body.pc-layout--sticky`; a deprecated `mode="icon-collapse"` alias remains). `SidebarItem`/`SidebarSearch` icon spans carry `pc-icon-hover-highlight`; the chevron + search magnifier are empty masked spans (core CSS `font-size:0` + mask). `Sidebar` also loads `@keenmate/pure-css/js/sidebar-flyout.js` (keeps collapsed icon-rail flyouts inside the viewport). **Sidebar/navbar/navmenu shell blocks are `pc-*`, not `pa-*`.**
- **New sidebar elements** — `SidebarSection` (`.pc-sidebar__section` flat heading `<li>`, `labelText`) and `SidebarDivider` (`.pc-sidebar__divider` rule `<li>`), siblings to `SidebarItem`. `NavItem` gains `isActive` (`.pc-navmenu__item--active`).
- **Search entry points** — the full set is now wrapped. **`NavbarSearch`** = the `.pc-navbar-search` pill *trigger* that opens the palette (core has no size modifiers for it — size the zone via `class`). **`NavbarSearchField`** = `.pc-navbar-search--field` inline *live search* — a real `<input>` + anchored `.pa-search-autocomplete` dropdown, Svelte-native (no core JS); one `globalSearch(query) → SearchResult[]` call, each row's optional `group` bucketed client-side into `.pa-search-autocomplete__section` groups (single round-trip, no fan-out); `SearchGroup` = presentation-only label/icon/order/`limit`. **`NavbarSearchInput`** (rc15) = `.pc-navbar-search--input` *type-and-go* — a GET `<form>` that navigates to a results page on Enter (no dropdown/palette). **`SidebarSearch`** (rc12/rc15) = `.pc-sidebar__search`, trigger (`onclick`) or type-and-go (`action` → `--input`); renders its own `<li class="pc-sidebar__item">`. **`SearchResults`** (rc15) = the page-level `.pa-search-results` list (the type-and-go destination): `variant` `compact`/`detailed`/`grouped` (buckets by `group`)/`cards`; `<mark>` highlight via `shouldRenderHtml` (also on `NavbarSearchField`). **`CommandPalette`** gains a `size` preset (`--sm/--lg/--xl`) + `width`/`offsetTop`/`resultsMaxHeight` CSS-var overrides (CSS-only). `SearchResult` carries `snippet`/`meta`/`type`/`href`/`group` for these surfaces. `CommandPalette` remains its own Svelte-native engine — `NavbarSearchField` does not share it (unifying the palette engine across surfaces is deferred to upstream work).

**Docs type-augmentation single-source:** the `window.Pa*` typings live in `src/lib/global.d.ts`. The docs app's alias to the lib *source* doesn't carry the ambient `declare global` across, so `docs/src/global.d.ts` bridges it with a `/// <reference path="../../packages/svelte-pure-admin/src/lib/global.d.ts" />` — pulling the lib's declarations into the docs program so a new `window.Pa*` API is picked up automatically (no lockstep edit). Only globals **not** in the library's public surface (the raw `split-button.js` helpers `toggleSplitMenu` / `closeSplitMenu` the OverflowToolbar demo drives) are declared locally in that docs file. (`packages/svelte-pure-admin/dist/global.d.ts` is a stale build artifact, regenerated on publish — ignore it.)

**Wrapper mechanics:** dynamic-import the IIFE inside `onMount` via `internal/core-js.ts` (SSR-safe — the IIFEs read `document` at eval time). `tsconfig.json` maps `@keenmate/pure-admin-core/js/*` to `internal/core-js.stub.d.ts` so `checkJs` doesn't lint the (symlinked, therefore in-program) core JS; the `window.Pa*` APIs are typed in `global.d.ts`. Init helpers that scan *descendants* (`PaRangeGroup`, `PaStatFit`) are given a `display:contents` host to init on.

**Import via the public `/js/*` subpath, never the physical `/src/js/`.** The app-shell engines that moved down into `@keenmate/pure-css` (`navbar-dropdown.js`, `fit.js`, `container-breakpoint.js`, `sidebar-resize.js`, `sidebar-flyout.js` — each preceded by the `pure-css.js` foundation runtime) are imported as `@keenmate/pure-css/js/<name>.js`. pure-css **rc06** tightened its `exports` map to expose only `./js/*` (mapped internally to `./src/js/*`) and hard-blocks reaching into `./src/*` — importing `@keenmate/pure-css/src/js/pure-css.js` fails the vite/rollup build with `Missing "./src/js/pure-css.js" specifier`. The `tsconfig.json` stub mapping key is likewise `@keenmate/pure-css/js/*` → `internal/core-js.stub.d.ts`. (This mirrors how `pure-admin-core/js/*` was always imported.)

## Breaking changes

Version-by-version breaking-change history lives in `CHANGELOG.md` (this repo) and `../pure-admin/packages/core/CHANGELOG.md` (upstream). Notable currently-load-bearing items already captured in the rules above (logical directions, runes-only, lowercase event handlers).

**Masked structural-affordance icons (core 3.1.0).** Core 3.1.0 unified every *structural affordance* icon onto the masked `--pa-icon-*` system: a `<span class="pa-icon pa-icon--NAME" aria-hidden="true"></span>` painted in `currentColor` via CSS `mask`, replacing per-component Font Awesome `<i>` / text emoji. The glyph re-skins from one `--base-icon-<name>` override across pure-admin + the pure-css shell + web components. **Only structural affordances migrated** — *decorative* glyphs (card title icons, badge content, profile-panel nav/avatar icons, list avatars, illustrative demo icons, prose) intentionally **stay** on Font Awesome/emoji. Modifiers: severity `--info`/`--success`/`--warning`/`--danger`, directional `--chevron-down/up/left/right` (one base glyph, CSS-rotated), and `--copy`/`--x`/`--clear`/`--refresh`/`--filter`/`--search`/`--check`/`--edit`/`--delete`/`--add`/`--ellipsis(-vertical)`/`--settings`/`--bell`/`--user`/`--favorites`. Swept wrappers: `SplitButton` + `RangeGroupCore` (empty `__chevron`/`__caret` spans, CSS-rotated on `--open`), `TabsScrollable`/`TabsOverflow`, `ProfileButton`, `SettingsPanel` toggle, the copy glyph on `Field`/`DescTableItem`/`BandedRow`/`AccentGridItem`/`PropCardRow`, `DetailPanel` close, `FilterCard` (no spin on masked refresh), and `ToastContainer` (severity glyph derived from `variant`; `iconClass` is now an override). Masked icons **can't animate a mask-image**, so spinners were dropped. Search-pill `🔍` and sidebar-search emoji stay (the snippet keeps them; CSS collapses via `font-size:0` and masks over). **Version-coupling:** the mask rules are 3.1.0 CSS baked into each theme — an empty chevron/caret span or a `.pa-icon--*` glyph renders **blank** on a theme built at older core. Rebuild/reinstall themes at 3.1.0.

**Masked icon family + modal title icon (core 3.2.0).** 3.2.0 (via CSS-only 3.1.1, a navbar profile-icon size fix) is additive over the 3.1.0 icon rework. Three new masked glyphs joined the family — **`--download`** (retires the last raw `fa-download` export/download buttons), **`--link`** (hyperlink/attach-URL), **`--external-link`** (opens-in-new-tab) — all via `var(--base-icon-*, …)`. `.pa-modal__title` gained an **optional leading masked icon**: `Modal` now has a **`titleIconName`** prop (originally `titleIcon`; a `pa-icon--*` affordance name, or any icon-provider name rendered via `<Icon>` — `success`/`warning`/`danger`/`info`/`delete`/…, rendered inside `.pa-modal__title`, colour via `currentColor`; `titleText`-header only), and `dialogService` gained an **`icon`** option (derived from `variant`, override with a name or `false`) that `DialogContainer` maps onto `titleIconName` — mirroring core's `modal-dialogs.js`. Other 3.2.0 changes need **no wrapper edit** (inherited from theme CSS): the coloured-header pattern already lives on the root `pa-modal--{variant}` we emit; palette-style backdrop-blur modal entrance + runtime blur toggle (`--pa-modal-backdrop-filter`) + `scrollbar-gutter`-trusting scroll-lock; and the foundation **runtime list-marker knob** `--pc-list-bullet-type` (a CSS var, not a `pa-list-basic--*` modifier → stays a passthrough, no `BasicList` prop). **Version-coupling:** the new glyphs / modal animation / list-marker knob are 3.2.0 CSS baked into each theme — rebuild/reinstall themes at 3.2.0 (docs themes come from local `../pure-admin-themes` rebuilt at 3.2.0; committed lock stays at registry 3.1.0 since `--path` overrides don't touch it).

**Table `--plain` + two-line cell + CSS-only fixes (core 3.3.0-rc).** The 3.3.0-rc series' *stable* surface (the printable `pa-document`/`pa-sheet` system was deferred at first and has since been wrapped; `pc-grid` is still deferred — see Known upstream gaps). **`Table` gains `isPlain`** → `pa-table--plain` (own-block modifier, rule 1): strips the themed header fill + body/stripe backgrounds so the table reads as a plain ruled grid (paper forms, embedded sheet grids); pair with `isBordered` for cell rules. The **two-line cell** — `pa-table__item-title` + muted-italic `pa-table__item-desc` stacked in one `<td>` (line-item name + spec, or name + email) — is plain cell *content*, not a `pa-table` modifier, so it needs no Table prop; authored as raw spans in the `/tables/standard` demo. New **CSS-only** utilities (pure passthrough, no props): `font-weight-{normal,medium,semibold,bold}`, `font-style-{italic,normal}`, `rotate-{90,180,270}`, `text-vertical`/`text-vertical-up` (writing-mode spine labels). Other 3.3.0-rc changes need **no wrapper edit** (theme CSS): checkbox tick colour → `--base-text-color-on-accent`; **`.pa-table td` row-height bug fixed** (rows now a uniform min-height, default 4.3rem, where before they were content-sized — a *visible* change on every table); sheet/document line-item tables auto-wrap in `.pa-table-container` on mobile; transient overlays (`.pa-settings-panel`/`.pa-profile-panel`/`.pa-toast-container`/`.pa-command-palette`) never print. **Removed the shadowed numeric `gap-*` scale:** core no longer re-declares the pixel-based `.gap-1…gap-20` that pure-css's `!important` spacing gaps already shadowed — the **pure-css numeric gaps (`gap-N`/`gap-x-N`/`gap-y-N`, same scale as `m-*`/`p-*`) are now canonical**; core keeps only semantic `gap-sm…2xl` + `row-gap-*`/`column-gap-*`. No runtime change (the pixel scale was already fully shadowed). **Version-coupling:** the row-height fix, plain-table backgrounds, print rules and utilities are 3.3.0 CSS baked into each theme — rebuild/reinstall themes at 3.3.0-rc03 (docs themes from local `../pure-admin-themes`; committed lock stays registry since `--path` overrides don't touch it).

**Component-token namespace `--pc-*` → `--pa-*` (core rc20).** Every *component*-layer custom property was renamed `--pc-*` → `--pa-*` so the property prefix matches the class prefix: `--pa-*`/`.pa-*` = pure-admin components, `--pc-*`/`.pc-*` = the pure-css **foundation** + app **shell**. Values are identical — only names change, **no back-compat aliases**. The **foundation keeps `--pc-*`** (surfaces, text `--pc-text-color-*`, links, `--pc-border-*`, `--pc-hover-bg`/`--pc-subtle-bg`, the role *identities* `--pc-primary-color`/`--pc-danger-color`/`--pc-success-color`/… (the old `--pc-accent*` is now `--pc-primary-color*`), the theme-slot palette `--pc-palette-1..9` + `--pc-on-palette-N-text-color` (formerly `--pc-color-N` + `-text`)), and the **shell keeps `--pc-navbar-*`/`--pc-sidebar-*`/`--pc-footer-*`/`--pc-local-sidebar-*`**. Renamed to `--pa-*`: role *fills/tints* (`--pa-danger-bg`/`--pa-success-bg`/…), sentiment (`--pa-positive`/`--pa-neutral`), icons (`--pa-icon-x`), and per-component vars any wrapper sets inline — **`--pa-command-palette-{width,offset-top,results-max-height}`** (CommandPalette), **`--pa-gauge-size`** (Gauge), **`--pa-kpi-*`** (`-accent`/`-edit-cell-min`/`-gauge-cell-min`/`-gauge-tick-pos`/`-gauge-tick-color`/`-bar-color`), **`--pa-local-detail-panel-width`** (DetailPanel), **`--pa-copy-hint-text`/`--pa-copied-text`** (Field/DescTable/Banded/AccentGrid copy-to-clipboard i18n), **`--pa-range-*`** (RangeGroup), **`--pa-chart-trendline-height`** (docs Sparkline), **`--pa-splitter-gutter-size`** (Splitter). All wrappers + docs demos synced. Because a theme's CSS bundles a baked-in core version, themes built at older core still emit `--pc-*` component tokens — mixing an old theme with rc20 components is the usual version-coupling gotcha.
